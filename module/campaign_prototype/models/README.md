# 战役 YOLO 第七版（十一类）

`campaign.onnx` 与 `campaign.json` 成对分发。运行时验证 SHA-256、类别集合、输入尺寸、输出格式与网格契约；模型缺失或不匹配时明确失败。类别顺序以元数据为准，代码不写死类别表。

- 范围：中文 Windows `1776×999`。旧五类为场景白／橙箭头、收集提示、展开／紧凑小地图圆环与普通／EX 关卡标记；新六类为地面机关未激活／已激活、电梯起点／终点、封路光幕、屏障立柱。
- 模型：YOLO11n，在 v6 九类模型上继续训练 30 轮的末轮权重，新增屏障两类；FP32 ONNX opset 17，输入 `1×3×640×640`，输出 `[1, 15, 8400]`，NMS 在应用侧完成。
- 阈值：各类别 `0.5`，电梯起点 `0.7`（起点误检代价高，训练项目按复核结果单独抬高）。

## 两条取图方式

| 类别 | 取图方式 | 说明 |
| --- | --- | --- |
| 场景箭头、收集提示 | 遮罩切片，6 片 640² | 沿用 v4 已验证流程，先遮住地图与 HUD，边缘 2px 内的框一律丢弃 |
| 小地图圆环、普通／EX 敌人 | 小地图面板裁剪 | 展开或紧凑面板由调用方裁好，letterbox 后推理 |
| 机关、电梯、屏障 | 全画面网格，8 片 640² | 契约来自元数据 `scene`：X=0/384/768/1136，Y=0/359 |

全画面网格只在**切片内部边界**做 2px 截断保护：内部边界上的框是被切断的符号，中心会偏，必须丢弃；画面真实边界上的目标是完整的，只把框裁回画面。逐片按类别抑制后再全局抑制，IoU 0.45。

## 已验证

- 应用侧数值对照：训练项目的 5 张回归截图共 22 个新类目标，应用的 `detect_grid` 与训练项目 `scripts/predict.py` 的输出逐个配对，框坐标最大差 `0.00000 px`、分数最大差 `0.000000`；OpenCV 与 PIL 两种解码结果一致。
- 导出数值对照（训练项目）：40 个切片上 PyTorch 与 ONNX 原始输出最大框差 `0.000885 px`、分差 `0.0000073`，见 `exports/v7/parity.json`。
- 旧五类回归（训练项目）：test 集 mAP50 97.48%、mAP50–95 84.81%；末轮 val mAP50 99.5%。
- 屏障两类（训练项目，训练集拟合）：光幕阈值 0.5 时 P=0.968、R=1.000，阈值 0.7 时 P=1.000、R=0.933；立柱 P=0.964、R=0.994。

## 未验证

- 新六类**没有独立的留出集**，上面的屏障数字只说明训练集拟合，不是未见章节的准确率；元数据的 `acceptance` 记为 `regression_only_no_independent_scoped_holdout`。
- 换模型后旧五类没有在应用侧重跑 v4 的验证集。v4→v7 的同帧 A/B 只覆盖到 1 个场景箭头（框中心移动约 0.3px，置信度 0.907→0.950），这 5 张截图里没有出现圆环、敌人和收集提示。
- 新六类尚无游戏内实测；识别结果目前只进入推图快照，没有驱动任何点击。

## 使用

```powershell
.venv\Scripts\python.exe -m pip install -r requirements-yolo.txt
```

模型由首次检测时加载并复用，无需安装 PyTorch 或 Ultralytics。应用侧入口见 `module/campaign/objects.py`：`detect_objects` 给出客户区像素坐标的场景目标，`detect_minimap_objects` 给出面板像素坐标的小地图标记；箭头与圆环的精确中心仍走 `module/campaign_prototype/perception.py` 的精定位。

`campaign.json` 是训练项目 v7 导出的原件，其中 `application_integration` 记录的是导出当时尚未接入；接入情况以本文件为准。训练环境、数据与复核页不随模型分发，见[训练项目](E:/CodexData/NIKKEAutoScript/yolo/README.md)。

## 应用侧回放

旧五类的应用侧回归仍用 `dev_tools/campaign_yolo_evaluate.py`：回放已复核帧，经 detect_scene／detect_minimap 与精定位链路计数，复核记录在 `dev_tools/campaign_yolo/*.json`。帧文件原在本仓库 `tmp/` 下，2026-10-08 迁入训练项目后本机只剩部分，缺失帧会被跳过并计入结果的 `missing_frames`。训练、导出与 PyTorch/ONNX 对照入口已从本仓库移除，统一在训练项目完成。
