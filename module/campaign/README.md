# 自动主线模块

正式入口保持 `module.campaign.campaign.Campaign`。地图、视觉与移动代码统一在本包，
实验命令只作适配器，不拥有第二套移动实现。

## 目录职责

| 位置 | 职责 |
| --- | --- |
| `campaign.py` | 资源与游戏窗口准备、上层场景及章节会话调度、正式任务入口 |
| `noncombat.py`、`scene_session.py` | 章节无关的剧情、换章、主页及方舟接管；独立页面输入与共享战斗按钮 |
| `execution.py`、`session.py`、`window.py` | 有限执行与战斗接管、生产 Device 会话、停止与输入护栏 |
| `goals.py`、`subgoals.py`、`scouting.py`、`run_state.py` | 目标选择、解封与电梯子目标、拖展开地图侦察敌人的路程排序、跨帧运行状态 |
| `report.py` | 日志用词与行格式：内部标识翻成中文、坐标与状态摘要的统一写法 |
| `trace.py` | 每次正式执行的截图归档、事件时间线与离线回放页 |
| `timing.py` | 分阶段耗时（单调时钟秒表），日志里的所有「耗时 x.xxs」都从这里取 |
| `map/` | 标注校验、章节资源定位与名称映射、静态道路、连通分区、道路编辑与坐标变换 |
| `vision/` | 小地图配准、YOLO 感知、箭头／离屏标记、场景地面配准、战斗接管状态识别；模型和模板也在此处 |
| `navigation/` | 共享 A*、切开路网、移动与镜头闭环、电梯、停稳反馈、共同会话接口 |
| `tools/` | 命令行实验、校验与回放、实验设置及采集器窗口；生产入口不导入此子包 |

正式会话和实验会话都复用 `navigation.movement.navigate` 与
`navigation.session.NavigationSession`。模板与 ONNX 模型在 `vision/assets/`、`vision/models/`，
资源常量从新位置读取。

## 启动与场景接管

任务可从野外、剧情、MISSION CLEAR、章节列表、主界面、方舟、前哨基地、战斗准备／战斗／结算启动，
不再要求先手动进入地图。`Campaign.run` 先启动不依赖章节的 `CampaignSceneSession`，
由上层 `CampaignSceneController` 处理页面；野外章节与难度连续三帧一致后才加载地图、定位小队。
其它页面只匹配相应区域的返回主页按钮，命中才点击；没有相关页面或按钮时重新截图。
不在每帧遍历所有菜单，不保证识别所有未知页面；页面一直无法处理时仍有界停止。

主界面优先点可靠引导箭头，无引导时匹配现有作战入口；作战选择匹配现有“前往地面”按钮。
方舟仍先点引导并等待五秒，匹配中央卡片感叹号；没有引导与中央图标时匹配返回主页图标。
剧情统一由上层处理，启动时无战斗归属，不把已结束战斗绑定到历史敌人；启动 EX 弹窗只关闭。
有旧章节时只有 MISSION CLEAR 设置严格的下一章与原难度约束；没有旧身份的章节结束启动
须先识别章节列表或跳转入口，不能接受弹窗消失后的旧野外瞬态。

章节会话离开野外时只抛 `SceneRequired`，不自己推进换章或按旧坐标回正。上层处理后重新确认
身份及小队；同章保留敌人、光幕、机关、累计失败次数、EX 避让和真实移动失败历史，旧投影与待执行点击
一律丢弃。不同章节／难度重新建立状态；各章通过循环接续，不递归重新准备设备和资源。
调试开启时，上层页面留档位于 `log/campaign/scenes/runs/`，章节留档保留原路径。

中文客户端验证路径：分别从主界面有／无引导、作战选择、方舟有／无中央感叹号、剧情、
章节结束及战斗／结算启动，确认在可靠野外前没有定位、侦察或地面输入；覆盖第 12→13 章
经方舟换章，以及同章从菜单返回后失败计数保留。未知页面超时、停止与窗口变化不发送盲点。
页面模板沿用现有语言资源，首次主界面入口与完整多章流程仍需游戏内复测。

## 开局与异常恢复后的十字扫描

主线推图每次建立章节会话时，首次选目标前必须完成一次十字扫描；开局缺少有效小队位置
或镜头未居中时先回正并重新实测，不用准备阶段的失败坐标扫描。异常恢复确认新位置后，
同样必须执行“恢复后”十字扫描，再记录恢复完成并返回规划。扫描收图后重新读取当前快照，
不把展开期间的场景观测直接用于后续点击。

扫描沿用中心及四向的有界流程，某方向配准失败不继续深入；至少取得一屏可信观测才算
本次扫描完成，零屏或扫描异常不能直接放行规划。扫描失败消耗现有恢复额度，不清零恢复
计数或目标失败记录。战斗、EX 或其它中断发生时保留待扫描标记，完成接管与必要定位后，
在下一次选目标前重做扫描；不因决策轮号已经增加而漏掉。

普通战后仍按需侦察，不增加每场战后的强制扫描。机关触发、电梯传送后的原有十字扫描保留。
“Boss 前遗漏补扫”是独立设置，默认关闭不影响开局与恢复扫描；收集品任务不新增开局扫描。

中文客户端验证路径：主线启动后应先出现“开局扫描完成”再首次决策；触发业务恢复后，应在
“主线自动恢复完成”之前出现“恢复后扫描完成”。另验证初始定位失败、零可信屏、扫描中的
战斗／EX、用户停止和窗口变化；不得跳过待扫描要求或在安全异常后追加输入。离线流程验证
不替代游戏内完整四向扫描及之后的移动验收。

## 业务异常后的主页重启

推图业务返回 `needs_review`，或最终定位／规划／战斗等业务异常需要结束时，每次任务最多执行一次
“返回主界面 → 重新进入主线”。原有轮内恢复和各阶段重试先完成，再触发此步骤，不因单帧漏检重启。
返回阶段使用上层页面按钮循环：确认章节列表才关闭、确认准备弹窗才关闭、确认结算才处理；
野外或其他支持页面只点已匹配的 `GOTO_MAIN`。确认主界面前不点作战入口、不重新进入战斗，
未知页无按钮则等待；五分钟仍未确认主页、返回过程失败或重启后再次业务异常，直接交人工。

同一关战败重试耗尽抛出 `BattleFailed` 时直接停止交人工，不返回主页重启，不重新进入主线或改打其他敌人。
用户停止、窗口移动／尺寸／句柄变化、鼠标驱动失败及 I/O／OpenCV 异常不追加返回主页点击。
普通失焦仍先等待恢复前台。正常完成和发现收集品的主动停止不触发重启；资源与设备只准备一次。
同章重新取得身份及小队定位，保留已清敌人、机关、光幕、EX 避让和路线失败次数，
不沿用旧投影或待发送点击；真正换章才建立新的状态。页面切换和重启不会续期任务级单次额度。

中文客户端验证路径：在野外发生最终业务失败，确认点击已识别主页按钮并重新进入；从章节列表、
准备弹窗、结算和方舟分别验证先关闭／返回而不是点进入；确认主页后才恢复作战入口流程。
同章失败计数不清零；第二次异常、手动停止、窗口变化和驱动故障不再发恢复点击。
另验证首次战斗加三次重打仍战败时，返回野外后直接结束任务，没有 `campaign_home_restart` 或重新进入主线。
离线按钮／流程回放不代替实际游戏退出与重新进入验证。

## 前哨基地指挥中心与页面按钮循环

前哨基地先匹配左上页面标题，再在客户区 `(850, 755, 1000, 855)` 内查找指挥中心卡片
右上角的蓝色感叹号；复用 `ark_notice.png`，门限为 0.7。命中后以锚点加 `(-65, +40)`
客户区像素点击卡片中心，记录 `outpost_notice`，不点右上角感叹号本身。红色 N 不作为引导
感叹号；未命中只处理已识别的右上引导，不用固定卡片坐标盲点。不增加双帧确认或额外重试。

上层使用与项目 UI 相同的页面按钮循环：截图、检查相关页面及按钮，命中后处理并进入下一帧。
通用按钮只在对应的客户区局部范围匹配，不遍历所有页面或搜索全屏，也不识别加载动画。
章节列表先匹配中央面板的 `CHAPTER LIST` 标题，只有面板确认后才 OCR 新章节；野外章节号
也只在野外确认后读取。未知页不调用章节 OCR、不盲点，只按既有轮询和五分钟时限换帧等待。
实际游戏加载及首次必要 OCR 初始化仍有耗时，不应以页面遍历或专门加载分支阻塞截图。

中文客户端验证路径：从前哨基地带蓝色感叹号的指挥中心入口启动，应识别并点击卡片内部，
随后进入剧情或指挥中心；红色 N、只有顶部任务提示或没有页面标题时不得触发卡片点击。
主页→方舟、方舟→剧情及前哨基地切换中，没有可处理按钮时应持续重新截图，不遍历菜单
或运行章节 OCR；章节列表标题确认后才查 `NEW CHAPTER`。覆盖停止、窗口变化、未知页超时
以及原方舟和指挥中心点击偏移。离线截图验证不代替游戏内页面跳转复测。

## 运行证据与离线回放

「推图设置」中的「调试模式」默认关闭，主线剧情与收集品任务分别保存该开关。关闭时不保存运行留档或
更新章节目录的 `last_field.png`，实时预览与正常推图不受影响，已有归档也不会被清理。
开启后，从下一次正式自动推图会话开始建立独立归档：

```text
log/campaign/<难度>_<章节>/runs/<时间戳>_<随机后缀>/
  index.html             离线回放入口（正常收尾后双击打开）
  run.json               章节、难度、实例标识与客户区尺寸
  events.jsonl           即刻落盘的截图、输入、观测、决策与停止事件
  events.js              正常收尾生成的离线回放数据
  summary.json           最终定位／目标、操作计数、错误与容量摘要
  last_field.png         最后实际采集的无损客户区画面
  frames/                全客户区 JPEG 与原始像素小地图 PNG
```

回放页提供上一帧／下一帧、进度拖动与自动播放；右侧列出该帧到下一帧之间的事件。
`input_before` / `input_sent` / `input_after` 分别表示发送前证据、驱动调用返回、发送后第一张
实际业务截图，不能把 `input_sent` 当作点击已生效或小队已停稳。输入坐标为屏幕坐标，事件中
同时保存客户区原点。地图开合记录请求与最终状态；定位失败帧保留错误原因和可用的配准指标，
观测事件保留小队／敌人／光幕／离屏标记，初始快照与规划事件保留目标依据。
`frame_ref` 指向最近保存帧及其采集时间，表示事件不一定有独立截图。

普通帧每秒最多保存一张，输入前后、地图开合、定位失败与显式预览强制留帧。
全部复用已有业务截图，不增加截图轮询、额外游戏输入或等待；编码与写盘仍有少量耗时。
全画面 JPEG 质量为 92，小地图 PNG 不缩放；需要逐像素分析最终错误画面时使用
`last_field.png`。每次运行不限制采样图片总容量，持续保存符合采样条件的截图，正常收尾另存
最后一张无损截图；归档写入失败只告警并停用归档，不改变输入闸门和任务停止条件。

每个章节保留最近十次已完成归档，在下次会话开始时清理更早的已完成记录；未完成归档不会
自动删除。原有章节目录的 `last_field.png` 仍更新，保持既有诊断路径兼容。
进程被强制结束时，`events.jsonl` 与已保存图片仍可检查，但可能没有 `events.js` 和完成摘要；
此时回放页不可直接播放。准备阶段尚未建立控制会话，不在该归档范围内。

游戏内验证：先保持调试模式关闭，在中文 NORMAL 第 38 章启动自动推图，确认实时预览正常且没有
新增留档、章节目录的 `last_field.png` 未更新；停止任务并开启调试模式后重新启动，检查主线离屏标记点击、场景拖动、展开
地图与定位重试前后的截图顺序；停止后打开本次 `index.html`，核对事件中的坐标、定位状态与
日志一致。战斗接管场景另检查准备弹窗／战斗／结算状态及相应按钮点击。测试取消或切换前台
窗口时，应仅释放鼠标，不为留证补发地图开合或点击。

## 移动停滞时推定光幕封锁

主线同一目标连续三次真实移动无可靠路线进展时，检查最新停稳小队坐标附近的光幕标注。
线段标注按小队到整段的最近距离判断，点标注沿用道路横断估计；使用既有 48 地图像素容差。
只有唯一标注符合且本章尚未推定过、当前未封锁时，直接记为 active 封锁并记录 `barrier_assumed`，
不要求能量幕检测，不添加视觉复核任务。路网实际变化后，为本目标重建进展基准，下一拍保持
刚取得的小队位置重新观测与决策，按新路网绕行或选择可达机关，不再向旧路点重复点击。
同一光幕每章只推定一次；确认机关触发后按中央视野关联解除对应封锁。
无唯一邻近标注、已封锁、重复推定或路网未变化时仍安全停止；EX 退出及收集品任务不适用。

实机验证：中文 NORMAL 第 11 章，小队在光幕2附近停住并连续三次移动无进展时，应记录
`barrier_assumed`（`obj_b7cbe1d7a1f2`），将该标注切入路网并重新选择目标；不新增 `review_block`
任务。同一光幕解除后再次停滞，不应重复推定续期。无标注及相邻标注歧义场景仍应停止。

## 光幕按对象独立更新

两帧中各自唯一关联到同一标注的光幕独立记为封锁，不要求整屏候选都成功。
其他对象的遮挡、截边、漏检、编号变化或跟踪组失败不否决已确认对象；失败对象的状态、
几何与时间戳保持不变，不能将其漏检当作解锁。指定光幕的存在复核也按对象处理；
目标未检出且还有未关联光幕时，仍保留原有消失复核保护。

中文 NORMAL 第 13 章验证路径：踩机关3后镜头移到光幕2／3附近，应先展开地图配准、
再收起面板识别中央双柱，记录光幕3距离与方向依据，仅解除光幕3；其他光幕封锁不变。
同屏光幕1可关联、其他光幕被顶部栏遮挡时，仍应记录光幕1封锁；不得整批作废。
另覆盖单标注、远隔光幕、双柱漏检、方向冲突与手动停止。截图回放不代替实际游戏验证。

## 机关触发后的光幕定位与回正

机关触发后镜头指向已解锁的光幕，展开小地图并使用两帧道路配准定位视野中心；
不要求小队箭头或圆环可见。按距离选择最近标注，不设置接受半径或最小分差；单标注或
与其他光幕独立的最近标注直接匹配。最近两标注中心间距不超过两者标注长度之和时，再用
YOLO 双柱脚点连线校验方向；检测前收起面板但不回正镜头，沿用模型门限，不增加确认帧。
标注方向经 `GROUND_TO_CLIENT` 换算后比较无向夹角，不混用画面与底图斜率；最近者方向误差
不得大于次近者，缺柱或冲突时保留原状态，不按斜率改选远处对象。只解除匹配编号，
记录 `mechanism_barrier_candidates`、`mechanism_barrier_located`；同屏其他封锁保持原状态，
不批量清除，也不以目标 `block` 字段决定解锁对象。
随后回正小队。两种小队标记都缺失时，仅此已确认的机关触发阶段允许一次中央区域短拖：
先用新视口确认机关标注位于面板边缘，最大拖动 280 客户区像素；记录 `mechanism_edge_recovery`。
短拖不能代替小队定位，之后仍需原箭头／离屏图标回正与实测圆环定位，再开始十字扫描。

## 实际操作统计与路线无进展保护

`SQUAD_REACH` 到点容差，不另设“移动一定距离就续额度”的门限。

仍累计失败。连续三次真实移动无可靠进展返回 `navigation_stalled`，不通过回正重扫清零。

## 小队道路归属与收图后的当前场景

候选整体道路分过线之后，实际小队坐标还必须通过 StaticMap 的既有道路归属检查；道路外坐标
保留 needs_review，并记录 `squad_on_road=false`，不写入导航起点、地图覆盖或敌人状态。

## 战后位置失效与恢复实测确认

战斗接管退出时统一清除旧小队坐标、导航报告和镜头参考，胜利也不能沿用移动到敌人之前的
位置。胜负、敌人清除和目标失败记录仍按原规则处理；清理不发送输入，战败、取消、窗口异常
同样不能留下可复用的旧定位。普通缓存复用必须同时满足小队输入与镜头手势序号未变化。

回正恢复在开始时清除旧导航证据，再取得本次实测。展开定位成功但收图后紧凑视野未通过时，
只要本次实测的小队位置仍有效、返回坐标一致且镜头回正检查通过，就记录
`recovery_position_confirmed=true`，不重复消耗剩余恢复次数。紧凑快照仍为 `reused`，
不附带展开矩阵、敌人或覆盖；仅凭旧缓存、只定位视口或失败帧不能设置此确认。
