# 自动主线模块

正式入口保持 `module.campaign.campaign.Campaign`。地图、视觉与移动代码统一在本包，
实验命令只作适配器，不拥有第二套移动实现。

## 目录职责

| 位置 | 职责 |
| --- | --- |
| `campaign.py` | 资源与游戏窗口准备、章节定位、正式任务入口 |
| `execution.py`、`session.py`、`window.py` | 有限执行与战斗接管、生产 Device 会话、停止与输入护栏 |
| `goals.py`、`subgoals.py`、`scouting.py`、`run_state.py` | 目标选择、解封与电梯子目标、拖展开地图侦察敌人的路程排序、跨帧运行状态 |
| `report.py` | 日志用词与行格式：内部标识翻成中文、坐标与状态摘要的统一写法 |
| `trace.py` | 每次正式执行的有界截图归档、事件时间线与离线回放页 |
| `timing.py` | 分阶段耗时（单调时钟秒表），日志里的所有「耗时 x.xxs」都从这里取 |
| `map/` | 标注校验、章节资源定位与名称映射、静态道路、连通分区、道路编辑与坐标变换 |
| `vision/` | 小地图配准、YOLO 感知、箭头／离屏标记、场景地面配准、战斗接管状态识别；模型和模板也在此处 |
| `navigation/` | 共享 A*、切开路网、移动与镜头闭环、电梯、停稳反馈、共同会话接口 |
| `tools/` | 命令行实验、校验与回放、实验设置及采集器窗口；生产入口不导入此子包 |

正式会话和实验会话都复用 `navigation.movement.navigate` 与
`navigation.session.NavigationSession`。模板与 ONNX 模型在 `vision/assets/`、`vision/models/`，
资源常量从新位置读取。

## 运行证据与离线回放

「推图设置」中的「调试模式」默认关闭，主线剧情与收集品任务分别保存该开关。关闭时不保存运行留档或
更新章节目录的 `last_field.png`，实时预览与正常推图不受影响，已有归档也不会被清理。
开启后，从下一次正式自动推图会话开始建立独立归档：

```text
log/campaign/<难度>_<章节>/runs/<时间戳>_<随机后缀>/
  index.html             离线回放入口（正常收尾后双击打开）
  run.json               章节、难度、实例标识与客户区尺寸
  events.jsonl           即刻落盘的截图、输入、观测、决策与停止事件
  events.js              正常收尾生成的离线回放数据
  summary.json           最终定位／目标、操作计数、错误与容量摘要
  last_field.png         最后实际采集的无损客户区画面
  frames/                全客户区 JPEG 与原始像素小地图 PNG
```

回放页提供上一帧／下一帧、进度拖动与自动播放；右侧列出该帧到下一帧之间的事件。
`input_before` / `input_sent` / `input_after` 分别表示发送前证据、驱动调用返回、发送后第一张
实际业务截图，不能把 `input_sent` 当作点击已生效或小队已停稳。输入坐标为屏幕坐标，事件中
同时保存客户区原点。地图开合记录请求与最终状态；定位失败帧保留错误原因和可用的配准指标，
观测事件保留小队／敌人／光幕／离屏标记，初始快照与规划事件保留目标依据。
`frame_ref` 指向最近保存帧及其采集时间，表示事件不一定有独立截图。

普通帧每秒最多保存一张，输入前后、地图开合、定位失败与显式预览强制留帧。
全部复用已有业务截图，不增加截图轮询、额外游戏输入或等待；编码与写盘仍有少量耗时。
全画面 JPEG 质量为 92，小地图 PNG 不缩放；需要逐像素分析最终错误画面时使用
`last_field.png`。每次运行采样图片上限为 256 MiB，达到上限仍记录事件并在正常收尾保留最后
一张无损截图；归档写入失败只告警，不改变输入闸门和任务停止条件。

每个章节保留最近十次已完成归档，在下次会话开始时清理更早的已完成记录；未完成归档不会
自动删除。原有章节目录的 `last_field.png` 仍更新，保持既有诊断路径兼容。
进程被强制结束时，`events.jsonl` 与已保存图片仍可检查，但可能没有 `events.js` 和完成摘要；
此时回放页不可直接播放。准备阶段尚未建立控制会话，不在该归档范围内。

游戏内验证：先保持调试模式关闭，在中文 NORMAL 第 38 章启动自动推图，确认实时预览正常且没有
新增留档、章节目录的 `last_field.png` 未更新；停止任务并开启调试模式后重新启动，检查主线离屏标记点击、场景拖动、展开
地图与定位重试前后的截图顺序；停止后打开本次 `index.html`，核对事件中的坐标、定位状态与
日志一致。战斗接管场景另检查准备弹窗／战斗／结算状态及相应按钮点击。测试取消或切换前台
窗口时，应仅释放鼠标，不为留证补发地图开合或点击。

## 移动停滞时推定光幕封锁

主线同一目标连续三次真实移动无可靠路线进展时，检查最新停稳小队坐标附近的光幕标注。
线段标注按小队到整段的最近距离判断，点标注沿用道路横断估计；使用既有 48 地图像素容差。
只有唯一标注符合且本章尚未推定过、当前未封锁时，直接记为 active 封锁并记录 `barrier_assumed`，
不要求能量幕检测，不添加视觉复核任务。路网实际变化后，为本目标重建进展基准，下一拍保持
刚取得的小队位置重新观测与决策，按新路网绕行或选择可达机关，不再向旧路点重复点击。
同一光幕每章只推定一次；确认机关触发后按中央视野关联解除对应封锁。
无唯一邻近标注、已封锁、重复推定或路网未变化时仍安全停止；EX 退出及收集品任务不适用。

实机验证：中文 NORMAL 第 11 章，小队在光幕2附近停住并连续三次移动无进展时，应记录
`barrier_assumed`（`obj_b7cbe1d7a1f2`），将该标注切入路网并重新选择目标；不新增 `review_block`
任务。同一光幕解除后再次停滞，不应重复推定续期。无标注及相邻标注歧义场景仍应停止。

## 机关触发后的光幕定位与回正

机关触发后镜头指向已解锁的光幕，直接展开小地图并使用两帧道路配准定位视野中心；
不要求小队箭头、圆环或能量幕可见。只有 48 地图像素内的唯一光幕标注才记为已解除，
并记录 `mechanism_barrier_located`；同屏其它封锁保持原状态，不批量清除。
随后回正小队。两种小队标记都缺失时，仅此已确认的机关触发阶段允许一次中央区域短拖：
先用新视口确认机关标注位于面板边缘，最大拖动 280 客户区像素；记录 `mechanism_edge_recovery`。
短拖不能代替小队定位，之后仍需原箭头／离屏图标回正与实测圆环定位，再开始十字扫描。

实机验证：中文 NORMAL 第 11 章触发地面机关1 `obj_5c8ea73e769c`，镜头转向光幕1且小队处于
画面顶部边缘时，应定位并仅解除 `obj_28cdd0cbb8d7`，保留光幕2状态；无箭头与圆环时先执行
有界边缘回正，再恢复实测定位和扫描。另验证中央标注歧义、配准失败、取消与窗口变化：
不得批量解锁或补发镜头拖动；普通恢复的缺少小队标记保护保持不变。

## Boss 续行与 EX 绕行

Boss 前遗漏检查通过后保留原 Boss 目标和地图坐标，补视野、重新决策或 EX 中断不会改选历史敌人线索。
发现新的待清普通敌人时仍先清怪；Boss 战斗确认胜利后释放续行目标。
敌人目标直点记录只证明移动指令的目的地，不证明已经到达或选中敌人。EX 弹窗关闭后先重新定位
小队并关联实际 EX；实际 EX 编号与直点目标编号一致时，才按原编号纠正类型并解除同编号主线、
执行与 Boss 续行引用，不另设位置改型容差。主线两帧关联过 EX 的 Boss 保留原 EX 编号供实际关联。
途中触发其他 EX、缺少实际编号、附近试点或绕行路点触发时，保留原目标、实际操作统计与路线历史，继续绕行。
实际关联到 EX 就记录 `ex_encounter_confirmed` 并保存其位置证据，原类型已是 EX、途中触发及无直点记录
均不跳过；只解除实际 EX 本身的引用，不改写不同编号的移动目的地。
同帧互斥敌人框交叠时，仅保留一条分类冲突线索并侦察复核，不生成确认战斗目标或沿用错误目标。
实际 EX 弹窗证据优先，同处冲突与单帧 Boss 误分类还原为一条 EX；不增加距离或置信度阈值。

Boss 胜利后先识别 MISSION CLEAR，确认章节结束时接管换章并禁用战前小队坐标复用；
未命中则仍严格复核原章节与难度。下一章入口处理后，必须确认下一章节号与原难度才重建会话；
换章等待超过五分钟直接安全停止，不执行旧章节自动恢复。

前置道路复核冷却中且没有其他可立即扫描的落点时，只观测与等待，不反复开关地图或寻找主线。
新帧解除疑点或冷却结束后恢复复核；累计三次失败直接返回 `scouting_incomplete`，不进入自动恢复
清空失败记录后重扫。冷却与等待不等于道路已确认，仍不放行未经检查的移动。

EX 弹窗只关闭，不进入战斗。关闭后重新定位小队，优先关联本帧附近的 EX；被小队遮挡时才使用近距离
历史位置。根据小队、EX、原目标的位置关系，在有效道路副本上避让 EX：小队处于触发范围内时先向外
退出，再沿安全路点绕行；原路线已经不经过 EX 时恢复前往原目标。避让不修改资源地图或清怪状态，
原目标实际操作统计与路线无进展历史继续累计。同处重复触发时扩大避让范围，最多三次；本章关闭 EX 弹窗最多六次。

若无法确认 EX 位置、原目标本身位于 EX 避让区、没有绕行道路或重复触发达到上限，会停止移动并记录
明确原因，不恢复穿过 EX 的旧路线。调试模式下记录 `ex_popup_closed`、`ex_bypass_begin` 和
`ex_bypass_waypoint`，包括原目标、小队、EX、避让半径及路点。

实机验证路径（离线通过不代表实机完成）：
- 中文 HARD 第 7 章，在 Boss 前检查读到敌人进度 33/34 后，确认补视野及后续决策始终保留原 Boss 坐标。
- 中文 NORMAL 第 10 章，从 EX 附近前往右上方普通怪，途中触发 EX 时应记录 `ex_target_preserved`，
  普通怪保持原类型与执行编号；随后生成避让路点、先远离 EX 再继续原目标。
- 主线两帧关联过 EX 的 Boss 确实触发自身 EX 时，应在重新定位后记录 `ex_target_corrected`，解除同编号续行。
- 复核失败冷却期间，确认没有重复开关地图；第三次失败应请求人工复核，不进入回正重扫。
- 检查窄路无绕行空间、目标与 EX 重合、重复触发及用户停止：不得进入 EX 战斗，也不得追加无依据的点击。

## 实际操作统计与路线无进展保护

`inputs` 与 `target_inputs` 仅统计成功发送的鼠标操作（含地图控件实际点击），不统计截图、识别、
窗口安全检查或地图已有目标状态时的返回；`gestures` 单独记录可能改变场景的手势，继续约束定位缓存。
不以单目标累计 32 次操作截断正常移动，操作总数只用于日志和留档。

地图展开最多三次点击、收起最多两次；镜头规划、定位、移动、近点试探、侦察与战斗继续沿用各自的
次数或超时上限。`navigation/progress.py` 按稳定目标编号保留无进展历史，只有实际地面点击后的可靠
停稳定位才检查：普通和安全绕行阶段比较冻结目标在同一道路上的历史最优剩余路程；退出 EX 阶段
比较冻结退出路点，或确认离开所有避让圆并能接上通往原目标的安全道路。有效缩短沿用
`SQUAD_REACH` 到点容差，不另设“移动一定距离就续额度”的门限。

重新规划、目标标记位置微调、地图开合及 EX 中断不清空失败记录；大幅来回走而不改善历史最优路程
仍累计失败。连续三次真实移动无可靠进展返回 `navigation_stalled`，不通过回正重扫清零。
到点范围内的触发试点仍由原有限试点控制，不伪装成路线进展。

中文 NORMAL 第 10 章实机验证：从 EX 附近前往右上普通怪，确认退出及后续绕行路段有
`movement_progress` 留档；累计操作超过 32 次但持续推进时仍继续原目标。另检查原地点击、
来回走、反复请求紧凑地图、地图展开失败与手动停止；不能将纯检查计为操作，不能以重规划恢复失败额度。
离线回放通过不代表已完成这条实机验证路径。

## 恢复阶段的章节身份复核

小队回正前先确认野外画面，收起展开地图并等待遮罩消退，再截取新帧校验章节与难度。
难度 OCR 门限为 0.7，章节号仍为 0.95；难度名称前最多忽略一个由装饰图标误识别出的非英数字符，
其余文本必须完整匹配 `NORMAL` 或 `HARD`。会话内复核读不到时最多检查三帧，明确读到其他章节或
难度时立即停止，不拿历史身份替代失败结果。启动时连续三帧一致的要求保持不变，不恢复总时限。

中文客户端实机验证：在 HARD 第 8 章展开地图后触发小队恢复，确认先收图再读角标；短暂 OCR 漏读
只换帧复验，不发送场景点击；实际换章、连续无法识别或手动停止时仍须中止。离线留档复验不代替实机验证。

## 光幕的可观测区域

光幕与立柱按 1776×999 客户区的顶部栏、左上小地图及右上任务栏矩形排除 HUD，
不再排除整条顶部 120px。检测框必须完整位于客户区且不与上述区域相交；底部仍只检查
客户区边界，不套用点击用的整条底部禁区。立柱辅助推算的光幕脚点也检查相同 HUD 区域，
进入遮挡区或离开画面时停止跟踪，不能据此认定光幕已经消失。

中文客户端实机验证：在 HARD 第 8 章将光幕移动到顶部栏下方的中央区域，确认已检出的光幕
不因其框顶 y 坐标小于 120px 被过滤；移动至小地图、任务栏或画面边缘时应拒绝遮挡／截断证据。
本项只修正检测后的区域过滤，不改变 YOLO 模型或输入预处理，不能代替漏检修复。
