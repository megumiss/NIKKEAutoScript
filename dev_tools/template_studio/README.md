# 模板工作台

首页为通用中文模板管理：选择功能、导入截图、裁剪与对比，再新增、覆盖或删除资源。
活动专用的场景关联、会话和 agent 校对流程通过顶部“活动流程”进入。
本工具是独立的本地 Web 页面，不需要构建 `webui/` 或桌面壳。

在仓库根目录启动（使用安装了项目依赖的 Python）：

```powershell
python dev_tools/template_studio.py
```

浏览器地址为 `http://127.0.0.1:12273`，活动会话入口为 `/events`，历史索引入口为 `/history`。
活动 CLI：`python dev_tools/template_studio/events/cli.py --help`；`gui` 子命令启动工作台。

## 通用模板管理

1. 在“功能与资源”中搜索并选择功能，目录直接来自 `assets/zh-CN`，包括剧情活动与小游戏子目录。可以按名称和 Button / Template 筛选现有模板。
2. 点击“导入截图”、拖入 PNG/JPG，或在非输入框区域粘贴截图；支持多张导入。工作台保存原始像素的 PNG 副本到 `tmp/template_studio/uploads/`，重新打开页面后仍可选择，原文件保留。
3. 在中间“截图与裁剪”的原图上直接拖动框选；拖动选区移动，拖动四角调整，滚轮缩放，右键/中键或“平移”模式拖动画布。方向键移动 1 px，Shift + 方向键移动 10 px，也可在右侧输入坐标。裁剪不需要先填写模板名称。中间画布按 720×1280 竖屏比例分配空间，截图选择在左侧，选区坐标与保存控件在右侧；窄屏时控件顺序排列。
4. 右侧“本次裁剪”随选区实时更新。切换 Button / Template 保留选区；默认显示局部细节，勾选“查看完整输出”可检查 Button 的黑底和原坐标。“重新框选”清空选区。
5. 新增时在右侧选择类型并填写名称，点击“保存新模板”；覆盖时先选择左侧资源，再裁剪并点击“覆盖当前资源”。确认路径后写入，对应功能的 `assets.py`（小游戏为 `assets_game.py`）同步生成。新增同名文件会被拒绝，必须显式选择已有资源再覆盖。保存后保留选区供继续调整；尚未保存时切换资源或截图会提示放弃修改。
6. 删除时选择已有资源，点击“删除当前资源”并确认。基础 Button 的 `.AREA/.COLOR/.BUTTON` 配套图也会列入确认并一同删除。使用已删除常量的功能代码需要同步修改。

| 类型 | 输出与约束 |
| --- | --- |
| **Button** | 需要 720×1280 截图；输出同尺寸黑底图，保留选区原坐标，用于识别与点击。支持已有 `.AREA/.COLOR/.BUTTON` 属性覆盖图 |
| **Template** | 支持其它尺寸截图；只保存选区像素，不缩放；名称自动加 `TEMPLATE_` 前缀。生成 `Template` 定义 |

已有 GIF 可预览、对比和删除；裁剪写入 PNG，不能用同名 PNG 隐式覆盖 GIF。
每次写入前备份受影响的资源及资产定义到 `tmp/template_studio/backups/<id>/`，`manifest.json` 记录原路径及备份文件。
生成定义失败会恢复本次变更；资源或定义被其它操作更新时拒绝写入，刷新列表后保留当前裁剪供重新对比。
刷新或关闭页面会丢失尚未写入资源的裁剪，页面会提示；上传截图副本保存在本地。活动会话有独立的持久化草稿。
此流程只管理中文资源，生成定义时使用项目的多语言查找与回退规则，不改其它语言图片。
保存后请按所选功能在游戏内验证中文识别与点击位置，构建和图片尺寸验证不能替代游戏内验证。

## 历史索引校对

启动同一个服务后，打开 `http://127.0.0.1:12273/history`，或点击工作台顶部的“历史索引校对”。
页面直接读取`data/history_matches.json`，按活动、阶段、场景、缺截图或待补模板筛选。
选择条目后对照原图与历史模板预览，修改活动、阶段、场景及模板勾选；缺图项可填写绝对路径或点击“选图”。
选图支持 720×1280 PNG/JPG，目录浏览每页 30 张，也可以新增条目或移除关联。
活动、阶段、场景和模板候选来自当前 YAML，历史资源目录只提供同名模板预览，不向清单追加其它模板。
每个阶段独立提供场景、说明和模板候选；即使勾选“显示全部”，也只显示当前阶段的模板。切换活动或阶段时仅保留新阶段清单中的已选模板；切换场景保留已选模板供人工核对。页面显示 YAML 的场景说明，不判断截图的游戏状态。

点击“保存修改”（或 `Ctrl+S`）后写回原 JSON，条目包含 `screenshot_file`、`event_id`、`phase`、`scene`、`templates`。
没有截图路径的条目归入 `missing`，补图后归入 `screenshots`；相同截图、活动、阶段、场景的条目合并模板列表；同一张原图可按阶段分别关联。
保存前校验图片存在、尺寸和可读性，并将原文件备份到 `tmp/event_studio/history_backups/`。
原文件被其它页面或程序修改时拒绝覆盖；可先“下载 JSON”保留当前修改，再“重新读取”。
保存时也会检查场景与模板是否仍在当前活动类型及阶段的 YAML 中，拒绝清单外条目。
修改不会自动保存；模板图片仅供预览，校对索引不修改游戏资源或活动会话。

## 活动专用流程

1. 新建活动会话，填写活动日期（不校验日期或位数，自动添加 `event_` 前缀）和名称，选择要复制的历史活动、本次阶段及 EVENTS 第 1 或第 2 位。类型随历史活动继承。创建时复制整套中文剧情资源、生成资产定义，并插入活动记录，原有记录依次后移。后续更新使用“追加阶段”，保留旧截图和已确认模板。
2. 图片列表仅显示 720×1280 的原始 PNG/JPG 截图，每页 30 张。导入后逐张选择所属阶段与场景；无需在图片上标注，也不必填写画面状态。相同阶段与场景可放多张截图，导入时默认使用会话当前阶段，也可以在场景下拉框中更正。
3. 导入后在右侧选择目标模板，在中间“截图与裁剪”的原图上直接框选。也可点击“生成 agent 任务”，复制说明发给 agent。任务清单只来自 YAML，所有待处理项都需从新截图重新裁剪。agent 信任用户关联的场景，直接使用对应截图；没有场景截图或无法定位裁剪目标时列出具体缺项。YAML 外的模板可以回到通用模板首页处理；也可使用独立截图工具 `dev_tools/template_capture.py`。
4. agent 完成后点击“刷新结果”，进入“校对与导出”。检查裁剪框、局部预览和历史参考；不满意时直接在中间画布调整选区，或填写意见后打回。尚无提案的模板也可直接框选。
5. 打回后重新生成任务，agent 会收到校对意见。所有必需模板确认后，点击导出，只覆盖本次确认的 YAML 模板；其它文件不受影响。

### 会话管理与删除

在“活动流程”页面点击顶部“管理会话”，在“管理已有会话”中选择会话。列表显示活动名称、ID 和“当前”标记，
下方显示截图数量与模板确认进度；“刷新列表”可读取其它页面或 agent 的更新。

删除当前会话：保留默认选中的“【当前】”会话，点击“删除当前会话”，核对名称与 ID 后点击“确认删除”。
也可以选中其它会话再删除。删除当前会话后工作区清空，可打开其它会话或创建新活动；删除其它会话不切换工作区。

删除会永久移除 `tmp/event_studio/<event_id>/` 中的截图关联、裁剪草稿、校对状态和 agent 任务文件。
原始截图、已复制或导出的模板、资产定义及 `EVENTS` 中的活动记录均保留；删除会话不会撤销创建活动，原活动 ID 仍不能重复创建。
确认期间会话被更新时会拒绝删除，请取消确认、刷新列表并重新核对。

### 手动截取

活动页中间为原图裁剪画布。选择模板时载入已有裁剪框；左侧选择来源截图，右侧下拉框或模板清单选择目标模板。目标选择、坐标和草稿保存集中在右侧，中间为 720×1280 竖屏画布；窄屏时上下排列。
模板名称与输出模式遵循 YAML 清单，不必填写文件名或另选保存目录。

- 左键拖动框选；拖动选区内部移动，拖动四角调整边界。“重新框选”清空当前编辑选区。
- 右键或中键拖动平移，滚轮以鼠标位置缩放；也可打开“平移模式”后左键拖动。支持适应窗口和 1:1 查看。
- 四个坐标框可直接输入原图整数坐标；画布聚焦时，方向键移动选区 1 px，`Shift + 方向键` 移动 10 px，加减键缩放。
- 实时预览保留原图像素，右/下边界不包含在选区内。越界、非整数、宽高不足 2 px 或全黑选区不能保存。
- “保存裁剪草稿”写入当前会话并返回校对页，来源标记为“手动截取”。修改已确认模板后会退回草稿；确认后通过“导出已确认模板”写入资源。
- 拖动只修改未保存选区；未保存时切换模板、截图或会话会提示放弃修改。会话被 agent 或其它页面修改时拒绝覆盖，并保留编辑器中的选区供核对。

## 数据存放与处理

工作目录为 `tmp/event_studio/<event_id>/`，被 Git 忽略：

| 文件 | 内容与用途 |
| --- | --- |
| `session.json` | 活动名称、复制来源、插入位置、截图绝对路径与场景/阶段、模板坐标、草稿/确认/打回状态、校对意见；页面与 CLI 共用 |
| `agent_request.json` | 本次待处理模板、场景对应截图、模板用途与截图提示、历史参考路径及输入指纹 |
| `agent_prompt.txt` | 可复制给 agent 的任务说明 |
| `agent_result.json` | agent 按下文协议生成的批量结果；可用页面或 CLI 导入 |

导入截图只登记原图路径，不复制或缩放文件；移动、删除或覆盖原图会影响提案预览和导出。
保存标注、新提案和校对状态会更新 `session.json`。新提案始终是草稿；生成任务不会调用模型。
页面与 agent 在同一台机器上工作，agent 通过上面的绝对路径读取数据。
过期的页面保存或批量结果会被拒绝，需要重新读取会话；批量结果导入前应保持输入与校对状态不变。
YAML 是唯一裁剪清单。页面和 CLI 读取会话时同步当前已开启阶段的模板：移除清单外项、补入新增项，更新场景、输出模式及可选属性。
同名模板保留已有裁剪及校对意见；输出模式变化时退回草稿重新校对。截图的人工阶段与场景关联保持原样，新拆分场景由用户在工作台重新关联。
同名场景按阶段分别展示，不合并首日和后续更新的模板或场景说明。任务候选及提案来源同时匹配阶段和场景。
任务生成、提案导入及导出同样受此范围约束；规则变化后旧任务结果失效，需重新生成任务。
服务按请求读取 YAML，修改规则后刷新页面即可；资源目录中的清单外手动模板不受影响。

最终导出写入 `assets/zh-CN/event_dated/<event_id>/`：

- `button` 保留 720×1280 尺寸与原始坐标，选区外填黑。
- `template` 保存原始像素的局部小图，文件名使用 `TEMPLATE_` 前缀。

默认导出使用 `button_extract.py` 的提取器，仅重新生成当前活动的资产定义。
活动列表维护在 `module/config/events.py`，`ManualConfig.EVENTS` 引用此列表。
第 1 项对应 `Event`，第 2 项对应 `Event2`。创建时按位置插入，历史记录全部保留。
当前仓库有资源时优先使用当前仓库，否则从 `NIKKEAutoScriptArchive` 查找；两处都没有资源的历史活动不可选择。
重复 ID 或目标目录已存在时拒绝创建。资源复制、定义生成或注册失败时回滚本次创建的目录。

新记录继承活动类型，章节/难度按选择的阶段初始化；小游戏和扩展玩法默认关闭，布局参数不从旧活动继承。
这些活动特有配置由用户维护，后续追加阶段也需同步检查 EVENTS 中的章节和难度。
已运行的自动化进程需要重启才能读取更新后的活动列表；工作台的新建下拉框会直接读取最新文件。

CLI 创建示例（同 Web 新建流程）：

```powershell
python dev_tools/template_studio/events/cli.py new --event-id event_20261029 --name "新活动" --base-event event_20261008 --position 1 --phase day1
```

## Agent 协议

读取任务文件、`event_template_rules.yaml` 和 `module/event/` 中相关通用逻辑。
历史参考来自创建会话时选中的活动，不逐项混用其它活动；未记录来源活动的会话从同类型历史资源中查找。
历史参考在当前仓库及 `D:/PCR/NIKKEAutoScriptArchive/assets/zh-CN/event_dated/` 中；原始历史截图在
`D:/PCR/截图`。规则库是模板用途/清单，尚不是经过跨活动验证的自动定位 skill。

1. 截图所属阶段与场景以用户手动关联为准，直接使用该模板阶段和场景下的候选原图，不判断或校验截图的实际状态。`state_hint` 和 `requires` 是给用户准备截图的说明，不作为 agent 筛选或否定已关联截图的条件。旧模板用于辨认裁剪对象，旧坐标只供参考；清单内模板必须重新裁剪，不能沿用旧图作为结果。
2. 在 720×1280 原图上定位，用整数坐标 `[x0, y0, x1, y1]` 表达选区，右/下边界不包含在裁剪内。
3. 按模板名、用途和历史参考确定裁剪对象及边界，例如关卡序号与 CLEAR 标记应分别定位；无需额外检查场景状态覆盖。
4. 优先按批量结果协议提交；仅在对应场景没有截图或无法定位裁剪目标时写入 `unresolved`，注明模板名、场景及具体原因，不要猜测坐标。
5. 不改动已确认模板，不自行确认，不导出资产。让用户刷新页面校对。

批量结果示例（`fingerprint` 必须原样取自任务文件；`source` 使用任务中的绝对路径）：

```json
{
  "event_id": "event_20261029",
  "fingerprint": "从 agent_request.json 复制",
  "proposals": [
    {
      "name": "MAIN_GOTO_EVENT",
      "source": "D:/PCR/截图/example.png",
      "box": [520, 700, 650, 750],
      "note": "选取活动入口文字，排除动态装饰"
    }
  ],
  "unresolved": [
    {"name": "LOGIN_STAMP_DONE", "reason": "在签到场景已关联截图中无法定位此模板的裁剪目标"}
  ]
}
```

将文件写到任务中的 `result_file` 后，用户可点击“读取批量结果文件”，或由 agent 执行：

```powershell
python dev_tools/template_studio/events/cli.py apply-result --event-id event_20261029 --file tmp/event_studio/event_20261029/agent_result.json
```

每项结果导入时验证名称、来源场景、坐标、输出模式及确认状态，整批验证成功才保存。
需要分步处理时可以逐项写入；必须显式指定活动 ID：

```powershell
python dev_tools/template_studio/events/cli.py propose --event-id event_20261029 --name MAIN_GOTO_EVENT --file "D:/PCR/截图/example.png" --box 520,700,650,750
```

逐项写入后不要再导入旧指纹的批量文件。重新生成任务会带上已保存草稿和打回意见。
批量结果不接受 `reuse`；有效草稿和已确认模板必须包含来源截图与裁剪坐标。

## 验证范围

本工具可以验证原图尺寸、坐标边界、全黑选区、必需项确认状态及结果归属。
这些检查不能替代游戏内识别：导出后按活动入口、普通/困难关卡、签到领取前后、任务奖励领取前后、
商店的路径验证相关中文资源，尤其检查相近状态是否误判。小游戏与其它语言资源不在此工具范围内。
