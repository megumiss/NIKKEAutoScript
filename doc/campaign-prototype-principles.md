# 战役地图原型：运行控制与导航原理

本文对应 [module/campaign_prototype](../module/campaign_prototype/README.md)，解释当前代码的数据流与边界。它是独立实验模块，不是自动推图任务。采集和 Wiki 配准详见[地图数据原理](minimap-wiki-principles.md)。

## 1. 从截图到移动计划

```mermaid
flowchart LR
    A[静态地图与 validation.json] --> B[MapPackage 校验]
    B --> C[取得窗口控制]
    C --> D[展开小地图并截图]
    D --> E[道路配准与小队识别]
    E --> F[镜头平移或局部落点计划]
    F --> G[重新核对窗口与地图]
    G --> H[左上角最小化]
    H --> I[一次输入及有限观察]
    I --> J[重新定位和结果记录]
    J --> K[释放驱动后写回执]
```

`live.py` 只在传入 `--move` 后移动；`run.py` 的 `--move`、`--pan` 和 `--click` 互斥。
`--move` 自动规划目标，后两者用于指定手势的独立实验。`camera_to.py` 只平移镜头，每一步调用独立子进程重新观测，
不发送小队移动点击。`match_scene.py` 只生成候选落点。

`goto.py` 保留旧寻敌识别函数，但其命令行入口只接受保存图片进行离线回放。旧 41 章缓存缺少新包的完整质量契约，不能通过这个入口继续现场寻敌。

## 2. 坐标空间及换算

| 空间 | 原点与单位 | 当前使用位置 |
| --- | --- | --- |
| Windows 屏幕 | 多显示器桌面像素，可有负坐标 | 虚拟鼠标输入、GDI 截图 |
| 游戏原始客户区 | 游戏内容左上角，`1776×999` 像素 | 面板开关、小队箭头、场景点击 |
| 项目标准截图 | 由截图接口定义，如 `1280×720` | 现有任务模板；未接入原型 |
| 展开地图 ROI | 客户区 `[644,280,1130,742)`，宽 486、高 462 | 标记检测与道路配准 |
| 静态地图 | 裁剪后 `map.png` 左上角，原图像素 | 小队位置、道路规划、Wiki 标注 |
| 旧标定平面 | 历史 `calibration.json` 的投影坐标 | 已测量场景位移矩阵的输入 |

客户区到屏幕：`screen = ClientToScreen(hwnd, (0,0)) + client`。窗口移动会改变原点，因此一个操作会话内记录原点并拒绝变化后的输入。Windows DPI 感知必须在读取几何前设置；非 DPI 感知进程看到的逻辑坐标不能直接作为驱动像素。

同宽高比截图按分轴比例换算：`client = screenshot_point * client_size / screenshot_size`。`screenshot_to_client` 拒绝越界点、非有限数值和比例不同的截图。黑边、裁剪、旋转不是简单缩放，须有另外的显式变换。

展开 ROI 到静态地图使用齐次单应矩阵 `H`：令 `q = H @ [u,v,1]`，则 `map = q[:2] / q[2]`。分母接近零说明点在投影地平线附近，`transform` 拒绝继续计算。`roi_to_map` 已含位置配准，不能再重复加 ROI 客户区偏移。

## 3. 地图包为什么需要校验

单独校验 `map.png` 不足以保证位置可靠：同一图片可能搭配旧投影、不同裁剪原点或另一难度的标注。`MapPackage` 在控制游戏前检查：

1. `map.json` 的版本、章节、难度与左上角像素坐标约定。
2. `validation.json` 必须完整绑定 `map.json`、`map.png`、`annotations.json`、`source/map_data.npz` 和 `calibration.json` 的 SHA-256。
3. 图片与标注使用同一底图哈希；实际 PNG 尺寸与元数据一致；所有几何和连接通过标注格式校验。
4. 已完成道路扫描，无未解决前沿；道路配准为 `joint_grid_road`，残差中位数不超过 3px，帧数大于零且全部定位，没有排除的未定位帧。
5. 裁剪框在原画布内，裁剪后尺寸等于底图尺寸，`capture.crop` 与顶层 `crop` 一致。
6. NPZ 的投影、画布、原点、帧位置和朝向矩阵与 JSON 一致，道路概率有限且非负。历史融合边缘可能略大于 1，加载后截到 1，不改变原文件。
7. 标定文件与包声明的客户区、ROI 一致；覆盖声明必须与扫描记录相同。

当前通过校验的 38 章包声明 `coverage=observed_roads`、`whole_camera_domain_verified=false`：可以在已有道路范围进行实验，不能称为完整章节地图。内容哈希用于一致性和版本绑定，不是第三方签名，也不能证明地图真值准确。

加载器按 `source.difficulty` 筛选点标注，再以 Wiki 编号建立目标表。普通包中可以保留困难标注供编辑，但默认普通运行只取普通点。普通包不会因传入 `--difficulty hard` 就变成经实测的困难地图；该身份不匹配会拒绝加载。

`prepare_package.py` 在同一文件系统的临时目录复制静态包，添加标定和哈希清单，再用同一加载器验收，最后发布新目录。它不重建地图、不修复配准、不改写难度，也不覆盖既有包。后续编辑了标注，应重新导入到新目录；运行中修改包会使旧绑定失效。

## 4. 小地图状态机

所有原型 `map_open` / `map_close` 都调用 [DriverWindow.reset_minimap](../dev_tools/minimap_reconstruct.py)。识别顺序是展开面板、紧凑地图、关闭图标；无法识别时停止。

| 当前状态 | 目标 | 输入 |
| --- | --- | --- |
| 展开 | 紧凑 | 点击展开面板左上角 `(658,269)` |
| 紧凑 | 展开 | 点击客户区开关 `(42,98)` |
| 关闭 | 展开 | 先打开紧凑地图，确认后再展开 |
| 已是目标态 | 保持视野 | `reset=False` 时不点击 |
| 未知 | 任意 | 保存错误并停止，不猜测开关位置 |

每次切换等待动画和状态确认，单次状态等待有三秒上限。采集和真实小队定位使用 `reset=True`，
先最小化再展开，使小地图回正并显示小队；远点规划中的镜头观测使用 `reset=False` 保留已平移视野。

地图蓝色占比是当前 UI 的状态判据，不是章节识别，也不是通用遮挡检测。战斗模块尚未接入，所以此时不修改 `SemiCombat` 的独立分支；正式复用时仍须统一其地图行为。

## 5. 输入、取消与结果契约

`runtime.Window` 复用采集器 `DriverWindow`，底层仍使用已有虚拟鼠标实现。它是独立实验适配层，没有接入任务调度的 `Device` 生命周期。

- 首次可以尝试取得焦点。开始控制后，失焦、尺寸改变、窗口移动或 STOP 都使下一次输入失败，不自动抢回焦点。
- `GuardedInput` 拦截点击、移动、按下和滑动；抬起鼠标不受这些检查限制，确保错误情况下仍能释放。
- `pause` 分段等待并检查状态；自适应参数搜索逐候选检查 STOP。单次底层手势和 OpenCV 调用仍有执行时间，取消不是硬实时中断。
- 入口在 `finally` 释放，`finish` 先关闭驱动再写回执。写盘失败输出到标准错误，已有取消或操作异常不会被覆盖；本来成功的操作若回执保存失败，也以失败退出。
- 采集异常保留扫描记录并直接释放；只在成功路径补做最小化，避免清理阶段重新点击不确定页面。
- `run_child` 检查子进程非零退出码。超时或取消时创建共享 STOP，等待最多 15 秒让子进程协作释放；不响应才强制结束。强制结束不能等同于已执行 Python `finally`，需检查驱动现场。

标准实验命令返回 `0` / `1` / `130`，分别表示命令完成、失败、取消。参数解析错误由 argparse 返回 `2`。回执的 `completed` 不表示到达、拾取或战斗成功；几何接近标注仍需独立结果判据。

记录绑定包含章节、难度、底图哈希和整个 `validation.json` 摘要。镜头控制要求来源回执成功、目标编号匹配、观测不超过 120 秒；子进程重新定位后核对视野中心变化不超过 12px，再比较当前道路掩码，差异超过 3% 即拒绝输入。时间戳本身不能保证画面不变。

## 6. 道路定位

### 固定投影

`probe.Localizer` 将实时道路与有效域按地图投影拉正，粗分辨率搜索全图，再在最佳位置附近细化平移。有效域排除边框、文字、红色标记和小队圆环。

评分是有效域内道路交并比：`IoU = intersection / (live_road + map_road - intersection)`。它不是旧 `goto.Localizer` 的归一化模板相关分数；两套数值不能互换。

固定投影要求最终 IoU 至少 0.80，粗搜索最佳与独立次优候选差至少 0.10。它保留为较早实验与对照入口；跟随镜头透视变化时优先使用自适应定位。

### 自适应投影

`AdaptiveLocalizer` 先搜索两组尺度／透视参数，再在最佳参数附近细化。最佳道路变换用 ECC 单应修正，但只接受道路采样点最大修正小于 65px、小队投影位置修正小于 25px 的结果。

接受条件是最终 IoU ≥ 0.85、粗候选与独立远处候选分差 ≥ 0.10，并且投影位置在地图内。保存 ROI、轮廓叠加和定位 JSON，以便检查失败原因；输出文件存在不表示定位已通过。

小队圆环必须唯一。镜头探索允许 `require_player=False`：无圆环时返回 `position_kind=viewport_center` 和 `player_roi=null`，仅描述相机视野中心。`run.py` 只有在 `position_kind=squad` 时计算小队到目标距离；`live.py` 要求真实小队位置。

## 7. 道路规划与场景落点

`route` 对道路掩码求距离变换，每 8px 取一个节点，净空大于 6px 才可通行。八邻域 A* 的边代价兼顾步长和净空；
对角移动要求两侧正交邻格也可走，防止切过墙角。自动移动用这条路径检查道路连通性与报告剩余路长，直接规划完整目标。
返回的约 100px 局部路点仅供旧离线对照及显式短移实验使用。

这条路径是静态道路的几何规划，不包含门、机关、剧情或动态障碍。常规移动由 `camera_navigation.plan_world_move`
先将目标移入画面、再点击交给游戏自动寻路，不能把 A* 长度当作实际行走距离。

平面地图通过当前 ROI→map 单应的逆矩阵求目标 ROI 坐标，再通过历史投影和 `A_INV` 换算场景位置，
以本次箭头锚点校正平移项，保留透视项。视野外的目标只用局部 Jacobian 估算拖动方向，避免跨透视地平线后方向反转。
场景矩阵仍是标定估计，移动后必须重新定位；未到达则按新的小队位置修正。

`sample_ground_anchor` 以白／橙箭头的动画中点向下补偿 90 客户区像素，得到与原标定一致的小队脚下锚点。
最多采样 48 帧，在 16 帧滑动窗口内验证两个周期，容忍每半窗口最多两帧漏检。横向漂移或小地图道路变化时停止。
大地图地面圆环检测已移除，`live`、`probe`、`run` 和管理界面统一使用箭头周期；详细条件见[地图标注说明](map-annotation.md)。
管理界面的到点、收集品、敌人模式，以及 `live --move`、现场 `probe`、`run --move` 均使用共享镜头规划器。
自动移动不再截成最多 70 地图像素或 240 客户区像素；完整目标可点击时直接点击，否则先在主场景平移。
远距离寻位在避开 UI 的场景区域内使用长拖动，横向最多 1728、纵向最多 810 客户区像素，每批最多三次。
批内以同一实测基准换算目标相对向量，两轴等比例缩放，累计拖动后扣除预计相对位移，不逐次外推透视。
响应增益由最近三批的小地图实测总位移与总拖动向量计算。
批末、预计相对位移完成、画面基本不变、估算失败或拖动预算用尽时，展开小地图重新配准。
画面比较只提示可能碰到边缘，不估算场景平移；重新定位确认无进展且目标仍不可点击时停止。
仅估计目标进入可点击区不会提前打断一批拖动，估算结果不能直接用于目标点击。
裁剪底图边界不等于游戏镜头边界；道路配准可信时，允许视野中心位于底图外，真实小队仍须在底图内。
小队离屏时保留原小队位置，视野中心只用于镜头换算；主场景截图用于身份检查和预览，不做地面配准。
单次计划最多平移 8 次；到边界、定位失败、失焦或取消时停止。点击后同时检查小地图道路与小队标记的连续稳定窗口，
避免镜头静止而小队仍在行走时提前结束等待。等待期间直接采样紧凑地图，不反复展开面板；
四帧圆环坐标跨度不超过 6px（1920×1080 归一化坐标）、共同可见道路稳定才返回，漏检时重新累计。
收集品模式以带放大镜的橙色倒三角出现作为停止条件，保存提示证据，不追加微调或拾取点击；
自动拾取引起的计数增加仍可作为反馈。旧 `movement_click` 的 240px 限制仅保留在离线对照路径。

远距离 `match_scene` 使用 Wiki 场景图的 SIFT 特征、比率筛选和 RANSAC 单应，要求足够全局及落点附近内点才标为
`reviewable`。这个字段表示可以人工复核；共享镜头规划器通过实时小地图定位完成自动落点，不依赖 Wiki 场景图。
跨区域机关与跨层导航仍未完成。

### 高低差与局部道路区域

第 39、40 章不能从二维道路重叠推断上下层连通，也不能沿用同一个场景矩阵。`surface_motion.py` 将变换绑定到指定道路区域：主场景使用双向匹配的 SIFT 特征，小地图使用双向光流；三分之一对应点留出验证，最大误差不得超过 3px。目标必须位于观测点的凸包内。选区混入凸起、台阶边沿或另一层道路时应拒绝，不能只凭整体多数点拟合良好就宣布有效。

已有有效局部标定的分层地图也接入共享镜头流程，仍使用自己的标定矩阵、支持域和道路掩码。
若完整位移超出实测支持域，只走受支持的落点；镜头定位点也必须落在已标定同层道路上。
接入远距离流程不会扩大局部标定半径或开放跨层移动。

`fit_calibration` 至少使用 6 次覆盖两轴的停靠样本拟合局部小地图到场景的仿射关系，另用至少 3 次停靠验证；训练／验证误差上限分别为 6px／8px，验证点仍须处于训练支持域内。`plan_click` 只使用目标道路自己的 `surface_id`、标定域和当前场景配准，不要求出发点与终点共面。地面落点确定后可交给游戏自动寻路。这些函数已有离线回归，但尚未收集完成可用于通用导航的现场标定包。

箭头被遮挡时，管理界面允许从本次任务已经验证的箭头锚点，结合小地图小队位移和两组静态地面配准恢复位置。
缺少基准、地面支持域不足或投影不一致时拒绝测量，恢复帧不成为下一跳参考。
第 40 章历史远点实验确认单击可绕行到达，事后 6 帧估计偏差为 5.7～6.1px；
该实验使用现已移除的圆环检测，结果不能作为当前箭头方案的移动精度验证。
此实验直接选择了可见地面点，不能证明小地图坐标到任意场景落点的换算已完成。

## 8. 当前验证与限制

必要 Python 检查、地图／Wiki／存储回归和 M0 故障用例见[操作与验证说明](map-annotation.md)。合成回归覆盖错误包、焦点、窗口几何、取消、写盘、释放和子进程失败；它们不能代替真实十次切换验收。

M0 首次真实切换因焦点丢失停止，鼠标正确释放；在操作者留出前台时间后复测十次全部通过，20 张状态截图和 20 次开关点击日志一致，最终保持紧凑地图并释放驱动。M0 没有执行战斗、拾取或自动推图闭环。后续已增加中文窗口第 40 章一次可见远点的绕行到达证据，但通用地图导航的支持边界仍不能由此扩展到该章全部道路。
