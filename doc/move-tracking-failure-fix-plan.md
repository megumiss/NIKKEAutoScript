# 移动测试「三路都不可用」失败的根因分析与彻底修复方案

适用范围：`module/campaign/navigation/camera_navigation.py` 的 `plan_world_move_compact` 紧凑闭环镜头规划。
本文是修复方案的评审稿，未改动任何代码。

## 1. 症状

`manual_move.py` 报错：

```
移动测试失败：帧间跟踪、全局配准与批末展开都不可用；未发送移动点击。
```

历史已修过多次，均围绕门槛数值微调（register IoU 0.86、needs_review 0.8、SQUAD_REACH 放宽），修完仍复发。

## 2. 失败现场证据链

证据来源：`log/campaign_prototype/manual_movement/dccb411fc40c7ac3c8f52649/`（chapter 38，target (1118.3, 509.1)，收集品模式）。

1. **起始状态正常**：起始紧凑配准 `accepted`（iou 0.8838），展开图小队定位 iou 0.91，两者偏差 5.8px。
   小队 (514, 665)，目标约 624 地图像素远，规划器发出一次 `(-1392, 560)` 客户区大拖动。
2. **链式跟踪失败是必然，不是偶发**：624 地图像素 ≈ 360 紧凑面板像素位移；`register`
   （`dev_tools/minimap_reconstruct.py`）只接受不超过面板最大边 0.65 倍（约 137 面板像素）的位移，
   超限种子全部跳过。离线全参数域复算确认：这一步无论怎么搜，链式跟踪都不可能成功。
   **是步长问题，不是搜索问题。**
3. **全局紧凑配准在此区域有 IoU 天花板**：对失败帧紧凑面板在 a∈[0.6, 3.4]、b∈[0.45, 1.56]
   全域复算，真实位置最优 IoU 仅 0.546（recall 0.81 / precision 0.68），低于 accepted 的 0.85
   和 needs_review 的 0.8。原因：38 章包 `coverage=observed_roads`，且近期道路修订／光幕封锁标记
   已烘焙进底图，该区域标注地形与实时小地图存在系统性差异。起始区域未被编辑过（0.91 通过）。
   **固定 IoU 门槛只在未编辑区域有效。**
4. **批末展开锚定死于同一天花板**：`anchor_viewport` → `AdaptiveLocalizer.locate` 硬性要求
   iou ≥ 0.85，实测 0.585（a 从 0.88 漂到 1.44）。展开定位给出的视野中心 (758, 438) 与紧凑
   全域最优拟合 (729.5, 511.3) 大体互证——**定位找对了地方，是门槛拒绝了它**。
5. 三路同时 None/失败 → `plan_world_move_compact` 抛出上述错误。

结论：三条追踪路径的失败同源（步长超限 + IoU 天花板），是**结构性**问题；只调门槛数值必然复发。

## 3. 用户修订后的共识与方案重定向

用户指出：**链式跟踪并不可靠**（历史调低其阈值正是因为它不可靠），且 IoU 0.8 已是下限，
0.45 不可接受。结合进一步取证，这一判断成立：

- 本次失败的展开帧间实测位移约 (-140, 58) 面板像素，在 register 的 0.65 上限内，
  但相位相关 seed 错误导致 ECC 收敛失败，帧间重叠只有 0.20~0.38，低于 register 的 0.86 门槛。
  即链式跟踪即使在「应该可用」的场景也会失败。
- 拖动落点区域（gaze ≈ (758, 438)）的定位其实找对了：锚定结果与两帧道路互算的位移一致。
  失败不是「找错位置」，而是该区域 IoU 物理上限只有约 0.63~0.70：
  - ghost（live 有而底图无）9814 px、missing（底图有而 live 无）9588 px，各占约 1/4；
    对照起始区域 ghost+missing 合计仅 ~9%。
  - 参数网格扩展（b 到 0.2）、更细 ECC、纯平移微调（仅 +0.02）都救不回来。
  - 38 章包 `coverage=observed_roads`、`whole_camera_domain_verified=false`，
    底图道路网在不同区域质量不均匀，是天花板的结构性来源。
- 判别力实验：容差 IoU（双方道路各膨胀 3px 后再算 IoU）在正确位置为 0.67，
  整体错位 (+200,+150) 后仅 0.15——判别间隔 4 倍以上，可作为低门槛判据；
  而原始 IoU 正确位置只有 0.63，任何逼近 0.8 的硬门槛在此区域必拒。

**因此方案重定向：不把可靠性押在链式跟踪或任何固定 IoU 门槛上，
而把「位置判据」从绝对 IoU 改为带几何先验的相对判据。**

### 改动 1（核心）：观测融合判据——预测-验证替代绝对门槛

每一帧定位接受与否不再看绝对 IoU，而是「多源证据一致性」：

1. 拖动指令给出预测位移（`panel_delta_to_client` 的逆 + 实测响应增益），
   配准候选与预测位置差 ≤ ~150 地图像素视为「符合先验」。
2. 双源互证：紧凑配准与展开锚定（或与预测）互相印证时接受，
   门槛用**容差 IoU**（膨胀 3px，正确位置 ~0.67 vs 错位 ~0.15，间隔充分）。
3. 单源时维持现有 0.8 门槛不动——不放宽，只在没有更硬证据时保守。

安全性依据：错位实验显示容差 IoU 对 ±150px 级错位的判别间隔 ≥4 倍；
且导航闭环每步有响应增益检查（response ∈ [0.2,3]）、stalled 检测，
到点判定由 `observe()` 的展开图 `reset=True` 小队权威定位承担，错误不累积到落点。

### 改动 2：步长与追踪能力解耦

单次拖动的面板位移仍封顶（约 0.45×面板最大边），但目的不再是「保链式跟踪」，
而是**保证每一帧都落在上一帧已验证位置的先验范围内**，使改动 1 的预测-验证
始终有界。远目标分多批，`max_pans` 预算内完成。

### 改动 3：register（帧间）预测种子修复

`goto.mr.register` 调用处把指令位移换算的预期平移作为 `prediction` 传入
（当前硬编码 `(0,0)`，相位相关在道路重复结构上给出错 seed 是本次链式失败的直接原因）。
种子命中后 ECC 从预期位置附近收敛，帧间重叠 0.20~0.38 的场景可被纠正。
链式结果仍只作为「互证证据」之一使用，不单独放行。

### 改动 4（数据侧，长期）：38 章底图区域质量补扫

在失败区域（(758, 438) 附近）补充扫描并重建 `map_data.npz`，把该区域
ghost/missing 比例降到起始区域的 ~9% 水平。代码侧判据放宽后，
数据侧补齐才是把 IoU 真正拉回 0.85 门槛的途径。

### 改动 5（可选加固）：批末锚定失败时失效热启动

`anchor_viewport` 失败时将 matcher 的 `warm_parameters` 置 None，强制下一帧全网格，
避免漂移参数邻域的小网格搜索延续偏差。

## 4. 补充取证（2026-10-13，针对「链式跟踪不可靠」的复核）

对失败现场两帧展开 ROI 的离线复算结论：

1. 帧间真实位移约 (-140, 58) 面板像素（由两帧各自的 `roi_to_map` 反解同一点得出，
   与锚定位置一致）；`register` 的 0.65 上限容得下该位移，但相位相关 seed
   ((-0.2, 98.7)) 与真值差 180px，ECC 收敛失败，帧间 overlap 仅 0.20~0.38。
   **register 失败的主因是 seed，不只是步长。**
2. 拖动后区域 (758, 438) 的定位结果是正确的（两种独立方法互证），
   但 IoU 天花板 0.63~0.70：ghost/missing 各 ~1/4，起始区域仅 ~9%。
   底图该区域道路网与实况存在结构性差异（38 章包 observed_roads、未全域验证）。
3. 容差 IoU（膨胀 3px）判别实验：正确位置 0.670，错位 (+200,+150) 0.151。
   膨胀 5/8px 亦保持 ≥4 倍间隔。

## 5. 验证路径

1. 用同一请求（chapter 38 → target (1118, 509)）重跑移动测试，确认：
   - `register` 带 prediction seed 后帧间 `camera_tracking=chained` 成为主路径；
   - 观测融合判据在拖动后区域（IoU 天花板 ~0.65）按「预测-验证 + 容差 IoU」接受；
   - 不再出现「都不可用」；
   - 到点后展开图定位仍 accepted。
2. 挑一个已知编辑过道路的区域再跑一次，确认融合判据生效、且错位场景仍被拒绝
   （对照实验：人为整体平移 +200,+150 的候选必须被拒）。
3. 改动 `.py` 执行 `python -m py_compile`；同步更新 `doc/campaign-prototype-principles.md`
   第 154-157 段（判据描述与实现一致）。
4. 数据侧：在失败区域补充扫描重建 `map_data.npz` 后复测，
   确认该区域原始 IoU 回到 0.85 门槛水平。
