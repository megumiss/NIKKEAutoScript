# PR #301 / #322 本地整合

整合基线：master `66e9964a`、#301 `126b154c`、#322 `a0667afe`。

## 最终行为

- 虚拟屏由后端会话管理器持有。停止或重启 worker 保留有效屏幕；删除实例和关闭后端时定向释放资源。
- 预览按观看者的刷新间隔采样后端已验证的会话，任务停止后仍可观看。采样核对桥接身份，屏幕重建或端口改变后拒绝旧帧。
- 启动、停止、删除和重命名共用实例生命周期锁。停止请求绑定接收时的 worker；取消删除/重命名请求不会遗留锁，也不会提前释放仍在清理中的锁。
- Web UI 多实例共用 manager 中的 OCR 模型；同设备 Termux + proot 开启 `OcrSidecar` 时，同一启动命令共用一个 ADB 辅助进程。辅助进程启动失败时回退到 manager 中的共享模型。
- `predict()` 与 `recognize()` 均通过代理返回结果，推理串行执行，调用间隔由各 worker 分别控制。停止单个 worker 保留 OCR 服务，关闭后端统一清理。直接运行 `main.py` 沿用脚本进程持有 OCR 的方式。
- 保留加密解锁密码和自动解锁功能；OCR 基准工具的检测参数可透传给模型。
- 自动解锁是否明确指定主屏仍待确认，本次沿用 #322 的输入行为。
- 前端产物与 Android 桥接 JAR 已由整合后的源码重新构建。JAR 使用 Java 8 字节码、D8 8.3.37、min API 28。

## 本地验证

- Python 改动语法检查；配置 JSON/YAML 检查；Git 差异空白检查。
- 虚拟屏、API、会话生命周期、进程管理、服务停止、驱动控制生命周期和 VDD 生命周期相关现有测试通过，共 68 项。
- 受控运行覆盖 worker IPC/观看者事件、旧停止请求、取消等待与清理、停止期间的启动取消、停机预览、会话替换及 OCR 参数透传。
- 共享 OCR 使用真实 SyncManager、两个 spawn worker 和模拟模型验证：模型只创建一份，生成器结果在推理锁内消费，文本与数字结果回到各自请求方，调用间隔互不影响，强制结束 worker 后服务可继续使用。
- 使用真实 TCP 辅助进程和模拟模型验证多实例、多语言模型共用一个启动器；实例重启继续复用，启动失败回退到已有共享模型，后端清理关闭连接和辅助进程，重复清理及关闭后的请求处理正确。未加载 Paddle 或运行真机推理。
- SPA 构建通过；Edge 无头浏览器验证慢响应不堆积请求、隐藏时暂停、恢复时继续及卸载时清理。
- 扩展 Windows 后台控制测试运行 74 项，其中 3 个既有用例失败（4 处断言），均已在未修改的 master 复现：`test_scroll_uses_cached_position_and_postmessage_swipe`、`test_failed_drag_waypoint_stops_and_releases_left_button`、`test_swipe_holds_left_button_on_every_waypoint`。

## 待完成的设备验收

本地使用模拟进程、桥接响应与临时配置验证并发路径，未执行真实游戏流程。建议在真机上依次验证：

1. 启用虚拟屏并启动任务，打开预览，确认 OCR 运行时画面仍更新。
2. 停止任务，确认屏幕与预览保留；重新启动应复用同一会话。
3. 停止后重命名实例并重新连接控制，确认稳定 ID 不变；删除实例应仅清理对应屏幕。
4. 断开并恢复 ADB、重建屏幕，确认控制不会回退主屏，预览不会显示旧会话帧。
5. 在同设备 Termux + proot 中启用 `OcrSidecar`，同时启动两个实例；确认同一启动命令只启动一个辅助进程，停止其中一个后另一个仍可识别，重启实例复用服务，关闭后端后辅助进程退出。关闭 `OcrSidecar` 重复识别，确认只在 manager 中加载模型。
   分别在简中、繁中、日文、英文、韩文界面执行文本按钮识别，以及竞技场数字、商店价格和仓库数量识别；确认 `predict()` 和 `recognize()` 的结果分别回到发起请求的实例。
6. 在 Windows 客户端、模拟器和 Docker 中验证启动、停止及预览公共路径。
