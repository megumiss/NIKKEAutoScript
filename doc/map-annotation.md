# 地图标注工具

入口：`python -m dev_tools.campaign.editor`。目录职责见 [编辑器说明](../dev_tools/campaign/editor/README.md)。这是独立的本地浏览器工具，不启动游戏控制，不需要管理员权限。依赖 Python 3.9+ 和项目已有的 Pillow、NumPy、OpenCV，不需要额外安装前端依赖或构建 SPA。

从 Wiki 批量下载普通／困难收集物并配准到共享底图，参见 [Wiki 批量导入与地图补采](wiki-collectibles-batch.md)。导入后仍可用本工具人工复核和编辑。

## 启动

在仓库目录、已安装项目依赖的 Python 环境中运行：

```powershell
python -m dev_tools.campaign.editor
```

默认递归查找 `data/resources/maps/` 下的运行地图，与 Wiki 导入共用目录，自动打开浏览器。完整采集与辅助数据存放在 `data/chapter_maps/local/`，不进入默认地图列表。网页只监听本机 `127.0.0.1:8766`。终端按 Ctrl+C 关闭服务。

指定单张地图或其他集合目录：

```powershell
python -m dev_tools.campaign.editor --map data/resources/maps/chapter_38
python -m dev_tools.campaign.editor --root data/resources/maps
```

`--map` 指向包含 `map.png` 和 `map.json` 的目录；未指定 `--root` 时，同级地图包也会进入下拉列表。`--root` 和 `--map` 一起使用时，后者必须在前者目录内。`--port 0` 可自动选择可用端口，`--no-open` 可关闭自动打开浏览器。

## 标注流程

1. 在上方选择地图包。需要核对道路时，将左侧图层切换为“实拍参考图”；两张图共用同一套标注坐标。
2. 在左侧选择标注类型：**普通收集品、困难收集品、地面机关、地面电梯、光幕（立柱连线）、电梯传送关系**。收集品、机关和电梯默认单击创建点，也可切换折线、多边形或矩形；光幕默认用两点折线连接两根立柱的地面端点，也可切换点工具标记中心，不支持区域或多点折线。名称、颜色可自行修改，名称不决定已分类标注的类型。
3. 通过画布上方的“普通／困难／全部”切换收集品显示，画布和对象列表同步筛选，机关、电梯、光幕及传送关系共用。默认只显示普通收集品；切换普通或困难时，当前收集品绘制类型也随之切换。选择另一难度的收集品类型会切换到对应视图；“全部”视图可同时查看两种。切换不会修改已保存数据，保存始终包含被隐藏的标注。未完成绘制时先完成或按 Esc 取消，再切换。
4. 在图上绘制，随后用“选择”工具选中对象。拖动对象移动位置，拖动白色顶点修改形状；右侧可精确输入坐标、编辑类型、名称与备注、插入或删除顶点。点、折线、多边形分别至少保留 1、2、3 个不同顶点；光幕连线固定保留两个不同的立柱端点，不能添加第三个顶点。
5. 先标注两部“地面电梯”，再选择“电梯传送关系”，依次点击起点电梯和目标电梯。勾选“新传送为单向”后，箭头由第一次点击的电梯指向第二部电梯；未勾选则为双向。已有关系也可在属性里修改方向。收集品、机关不能作为传送端点；已有传送关系的电梯需先删除关系才能改成其他类型。
6. 点击保存或按 Ctrl+S，将标注写入当前地图目录的 `annotations.json`。刷新或重新打开地图会加载已保存内容。右侧“文件与副本”可下载当前 JSON，或重新读取磁盘文件。这些标注不会自动触发导航或战斗逻辑。

| 工具 | 操作 | 快捷键 |
| --- | --- | --- |
| 选择 | 单击选中；拖动对象 / 白色顶点 | V |
| 平移 | 按住鼠标拖动；任何工具下也可按住空格拖动或使用鼠标中键 | H |
| 点 | 单击创建 | P |
| 折线 | 连续单击添加顶点，双击或 Enter 完成 | L |
| 多边形 | 至少三个顶点，双击或 Enter 闭合 | G |
| 矩形 | 从一个角拖到对角 | R |
| 电梯传送 | 依次点击起点电梯、目标电梯，自动选择电梯传送关系类型 | C |

滚轮以鼠标位置为中心缩放；“1:1”恢复原图比例，“适应窗口”显示全图。绘制时 Backspace 撤回最后一个顶点、Esc 取消本次绘制。Ctrl+Z 撤销、Ctrl+Shift+Z 或 Ctrl+Y 重做；文本输入框内保留原生文本撤销。Delete 删除选中标注，删除对象时同步删除相关连接，可撤销恢复。

## 手动修订道路

左侧「道路修订」提供画笔补路（B）、橡皮擦（E）和多边形填充（F）。
画笔直径为 1～160 个原图像素，缩放不会改变实际宽度；单击可画一个点，按住拖动可连续绘制。
多边形连续单击添加顶点，双击或 Enter 完成；「多边形操作」可选择补齐道路或擦除区域。
Esc 取消未完成操作，Ctrl+Z 撤销、Ctrl+Shift+Z / Ctrl+Y 重做（撤销只在保存前有效）。

道路修订与收集品标注分别显示，「显示道路修订」可切换查看原图。
切到实拍参考图时，修订以半透明叠加，便于对照。
Ctrl+S 保存时把待保存的道路修订**直接写入原始数据**：`map.png` 的对应像素被重写为道路色或背景色，
平面地图同时把 `source/map_data.npz` 的 `terrain_probability` 置为 1（补路）或 0（擦除），
`map.json` 与 `annotations.json` 的图像哈希一并更新，道路连通区域随之重建；保存后不再保留独立的修订层。

道路底图统一为双色：道路蓝 `#2d8dc7`、背景 `#1e2b37`；
覆盖率与不确定概率带仍可从采集包里的 `coverage.png`、`terrain_mask.png` 诊断图查看，不进运行底图。
擦除的语义是"这里不是路"，因此擦除区域被重写为背景色，与周围地面融为一体。

首次写入前会把原始 `map.png`、`map.json`、`annotations.json` 和 `map_data.npz` 复制到
本地备份目录 `data/chapter_maps/local/packages/<地图>/.annotation_backups/terrain_original/`（不进版本库，
也不被资源同步覆盖），之后的烘焙不再覆盖该备份。
注意 `data/resources/maps/` 是资源仓库的本地同步副本，烘焙结果需另行提交回资源仓库，
否则下次资源同步会被覆盖。

## 恢复历史版本

右侧「文件与副本 → 历史版本」列出当前地图可恢复的备份，点击即恢复并重新加载：

- **恢复原始地图**：整体回滚首次道路修订前的 `map.png`、`map.json`、`annotations.json` 和概率缓存。
- **恢复标注备份**：回滚某次保存前的 `annotations.json`（每次保存自动备份），几何重新绑定当前底图。

恢复前会把当前标注另行备份，恢复后道路连通区域自动重建。
底图哈希随恢复变化，Wiki 匹配缓存随之失效，需重新匹配。

## 道路连通初判与人工修订

各章节地图目录中的 `connectivity.json` 保存道路连通初判和修订后的结果。现有第 1～48 章均已生成。
道路由扫描概率缓存叠加人工道路修订得到；分区在全分辨率道路掩码上按
八邻域计算（道路像素实际连通即算一个区域），再重采样到 8px 网格存储。

左侧「道路连通区域」提供以下操作：

1. 勾选「显示区域编号与连通修订」，切换「自动初判区域／修订后的区域」比较结果。相同编号表示步行连通。
2. 「绘制分隔线」：沿误连位置单击添加顶点，Enter 或双击完成；线应横跨需要切断的道路，宽度为 8～160px。
3. 查看即时区域预览，使用列表「删除」、Ctrl+Z 撤销或 Ctrl+Shift+Z 重做。Ctrl+S 保存后重新打开仍可继续修改。

人工修订按原图坐标保存在 `annotations.json.connectivity_edits`，区域编号是重新计算的显示编号，不能当作永久 ID。
不同区域之间只能通过已标注的电梯传送关系前往，不支持人为添加跨区域步行连接。
分隔只影响寻路图，不改写道路图像或定位证据；补路、擦路仍使用原有道路修订工具。
平面导航读取保存的有效区域，跨区域时规划电梯中转；分区、A* 和电梯判断使用同一份连通结果。

连通文件记录算法版本、底图哈希、道路掩码哈希和连通修订哈希，包含自动／有效区域的编号、节点数、范围、
标签位置与逐行压缩网格。打开或保存地图时会重建缺失、过期的数据，保留人工修订；运行副本绑定该文件哈希，
运行时不接受过期数据。新扫描导出与实验包导入会携带连通文件。需要重新批量生成时执行：

```powershell
.venv/Scripts/python.exe -m dev_tools.campaign.maps.connectivity --root data/resources/maps
```

## 正式扫描

右侧「地图扫描」可指定章节、扫描步长；默认步长为 120，保存帧间距默认 80px。先把游戏打开到对应普通章节的野外页面，再点击「开始扫描」。
扫描会核对章节号并展开小地图，采集时保持游戏窗口在前台。

- 采集后执行平面重建和导出，扫描任务自动串联上述处理。
- 页面显示阶段、已保存帧数与日志位置。「停止扫描」请求协作退出，正在计算的阶段可能需要等待；
  已采集帧保留。「打开扫描结果」只在任务成功且地图包校验通过后可用，切换时仍检查未保存编辑。
- 使用默认运行目录时，完整扫描写入 `data/chapter_maps/local/captures/scans/<任务 ID>/chapter_XX/`；成功后自动将运行必需文件导出到 `data/resources/maps/scans/<任务 ID>/chapter_XX/`（暂存目录，不提交），供「打开扫描结果」使用，不覆盖既有地图或修订。显式打开其他本地地图集合时，仍在该集合的 `scans/` 下输出。
  `.processing/` 保存中间证据，不会进入运行目录。
- 「采用为本章运行地图」把扫描结果导出为 `data/resources/maps/chapter_XX`：已有运行包与它拆出的 `runtime_extras` 整体移到
  `local/history/replaced_<时间>/`，`scans/` 下的副本随即删除，完整采集仍在 `captures/`。导出即精简（见「文件与坐标」）。
  旧标注坐标属于旧底图，不自动迁移，采用后重新导入 Wiki 或手工标注。
  命令行等价于 `python -m dev_tools.campaign.maps.runtime --source <包> --destination data/resources/maps/chapter_XX --replace`。
- 同一编辑器中的扫描与小队移动互斥。

## Wiki 和移动测试

手动修订在保存时已烘焙进 `map.png` 和道路概率缓存，`annotations.json` 不再保留独立修订层。
Wiki 缓存绑定底图与几何，收集品对象变化不会触发全部重新匹配；道路变化（底图哈希变化）会使旧匹配失效。
导入收集点保留既有道路笔画和人工标注。扫描的隐藏 `.processing` 包不参与 Wiki 地图选择。

右侧管理区分为「对象、Wiki、移动、扫描」四页，左侧道路修订与显示选项可折叠。
在「Wiki」页点击「匹配 Wiki 标注」，会使用当前地图包和已保存道路修订，预览普通／困难的通过数及待复核项；
「导入通过的标注」只增量添加已通过项目，保留已有坐标。匹配期间标注版本变化会阻止导入，需要重新匹配。

「移动」页显示当前地图的标定状态。所有平面地图统一使用第 38 章现用标定，不限制章节；
每张地图仍按自己的小地图投影换算位移，不直接复制第 38 章的地图坐标。

保存道路修订后，让游戏进入对应普通／困难章节，在道路上选点并点击「移动到目标」。
收集品／敌人行为仍需实际触发反馈，不将到达附近当成拾取或战斗成功。

到点、收集品、敌人三种模式共用远距离移动流程：目标已在有效场景内时直接点击完整目标，
目标离屏时先平移主场景，再用小地图重新定位目标并点击，交给游戏自动寻路。
每次计划最多平移 8 次，触及镜头边界或定位失败则停止；
单次镜头拖动按方向选择可用场景区域：横向最多 1728、纵向最多 810 客户区像素（1776×999 客户区）。
斜向保持拖动方向并取可用区域容纳的最大幅度，整段拖动避开小地图、顶部和底部固定按钮。
每次重新定位后测量实际镜头推进比例，用最近三次有效测量的中位数调整后续拖动幅度。
移动后根据小队标记与道路确认停稳，再重新定位和修正。界面显示本次任务累计的镜头平移次数。
等待期间保持紧凑小地图，间隔展开取得新快照后立即收回；不使用展开面板持续显示的旧画面判断停稳。
移动开始和移动后的真实小队定位也先最小化再打开，使小地图回正并显示小队位置。
小地图切换通过控件外框和面板状态确认；漏点时仅在原控件仍可见的情况下重试，最多点击三次。
移动的地面锚点通过小队头顶的白色／橙色向下箭头确定：最多采样 48 帧、间隔至少 0.2 秒，
在 16 帧滑动窗口内验证动画，每半窗口至少保留 6 帧有效箭头；少量漏检会继续采样，
用动画上下极值的中点消除浮动，再向下补偿 90 客户区像素，与原地面点击标定保持同一坐标含义。
该偏移在 1776×999 客户区、第 33 章现场测得；不适用于任意窗口缩放。白色、橙色和高亮笔画分别匹配，
同一箭头模板覆盖多个尺寸，保留 0.72 分数门槛与竞争候选检查。独立命令与管理界面共用箭头周期采样。横向漂移、小地图道路变化、身份变化或取消请求会立即停止；
采样耗尽后仅允许下述小地图辅助恢复，否则保存截图并停止。箭头换色、遮挡和不同道路高度的移动精度需按现场验证步骤分别核对。

场景墙面和地面不共面，因此标定测量局部点击位移，不用整幅场景的单个透视变换。
标定仅适用于该地图、难度、道路版本及采样附近的同层区域，不能外推到另一层或整个章节。
跨空洞、擦除区、缺少同层道路证据或超出标定范围时停止。修改道路后需重新标定。
短距离移动中，全局定位发生歧义时可以跟踪已验证的现场原帧，在不同局部范围做留出角点检查，合格结果间
坐标差不超过 3px；仅一个范围合格时须至少有 12 个对应点、4 个留出验证点。
固定参考跟踪失败时，允许两组直接通过固定参考定位的现场帧交叉恢复，位置差不超过 6px；恢复帧不成为
下一跳参考，避免逐步累积漂移。参考帧绑定地图、几何、道路修订和难度。
直接验证的辅助参考帧会保存在 `.movement_reference/<difficulty>/`，供下次移动任务恢复定位；
图片损坏、绑定不符或来自交叉恢复的帧不能作为辅助参考。
箭头持续丢失时，从本次任务上一次有效的箭头锚点出发，以小地图小队位移估计当前位置，
再用两组周围静态地面配准交叉核对。只在位移受支持且两组投影一致时恢复点击锚点，
恢复结果不作为下一跳基准。没有箭头基准、只有视野中心或地面配准失败时停止；
小地图小队标记也不可见时有限重试，持续失败不追加点击。Wiki 和小地图上的小队标记识别保留。

「到点」模式会消费已保存的点状地面电梯和电梯传送关系：步行道路不连通时，
按单向／双向连接规划中转，逐段点击入口，确认传送后继续最终目标。支持串联多部电梯；
折线、多边形电梯没有唯一点击位置，不参与自动移动。收集品、敌人模式不自动执行传送。
出口确认要求连续两次小队定位：入口道路已不可达、出口道路可达，且距出口标注不超过 96 地图像素，
允许游戏传送后自动走离平台。每段入口最多三次移动；已停在入口但未触发传送时只做有限等待，失败后停止。
跨区后清除上一段箭头锚点。到达判断始终针对最终目标，停在入口附近不算完成；
章节、难度、标注版本、停止文件、总点击次数和十分钟上限仍贯穿整个任务。
扫描与移动测试互斥。

第 48 章普通模式现场复现：保存点状电梯 `(527.9,707.6) ↔ (671.3,375.5)` 的双向关系，
从下方道路在「到点」模式选择 `(920,200)`。2026-10-08 实测单个请求自动通过电梯并连续两次确认到达，
最终定位 `(929.4,188.8)`，距目标 14.6 地图像素，共四次移动点击；反向返回下方道路也已通过。
记录在 `log/campaign_prototype/ch48_elevator_navigation_20261008/`；多段电梯和单向限制另由离线回归覆盖，
未据此宣称其他章节的机关交互已验证。

## 文件与坐标

- 坐标始终为原图像素：左上角 `(0, 0)`，X 向右，Y 向下。缩放、平移和切换参考图不改变保存坐标；小数保留到 0.1px，这只是记录分辨率，不代表地图的实际定位精度。
- 点、折线、多边形保存为 `point` / `polyline` / `polygon`；矩形保存为四顶点 `polygon`，之后也可自由调整形状。`category` 保存标注类型：`normal_collectible`、`hard_collectible`、`ground_mechanism`、`ground_elevator`、`ground_barrier`、`elevator_connection`。收集品同时写入 `difficulty: normal/hard`。`label` 是可编辑名称，`color` 为 `#RRGGBB`，`note` 是备注。传送关系沿用连接的 `id` / `from` / `to` / `directed` 格式，端点必须是不同的地面电梯。
- 光幕标注使用 `category: ground_barrier`，几何为中心 `point` 或两根立柱地面端点组成的两点 `polyline`。
  标注只提供位置与封锁段，不预设开关状态；实际检测按最近标注关联，不设固定距离上限，
  连续两帧实际识别到同一标注的光幕后才封路。立柱单独可见不能作为封路或解除封锁的依据。
  光幕确认必须有本章预标注，缺少标注时拒绝确认，不再从检测框估算落点；解除封锁仍要求
  指定编号的可靠视觉复核。
- 兼容没有 `category` 的旧标注：优先使用已有 `difficulty` 或 `source.difficulty` 识别收集品，也可识别“普通收集品／普通收集物”“困难收集品／困难收集物”及“地面机关”“地面电梯”标签（可带空格分隔的后缀）。无法判断的旧标注保持可见，可在右侧手动指定类型。读取和筛选不迁移文件；手动改类型会更新 `category` 和收集品 `difficulty`，保留 Wiki `source` 来源记录。旧的普通连接仍可编辑，转换为电梯传送时会校验端点类型。
- 保存更新 `annotations.json` 和配套的 `connectivity.json`，不修改底图、参考图或投影。道路操作保存在可选的 `terrain_edits` 数组，
  与标注对象独立，沿用相同的备份、撤销与并发保护。老文件没有此字段时视为没有道路修改。
  底图尺寸、SHA-256 和标注绑定必须一致，参考图也必须与底图同尺寸。
- 每次覆盖前，运行地图的原标注备份到 `local/packages/<地图相对路径>/.annotation_backups/`，再通过临时文件原子替换。显式打开其他本地地图包时，备份仍在包内。恢复备份时先保留当前副本，再将选中的备份复制为 `annotations.json` 并重新加载。
- 未保存修改在离开网页或切换地图时会提示。若其他窗口或程序已经修改标注，保存会拒绝覆盖；先下载当前副本，再重新加载并比较。下载副本不等于保存到地图包。
- `data/resources/maps/` 是资源仓库（NIKKEAutoScriptResource）的本地同步副本，随资源仓库更新而非主项目提交；`local/` 放完整采集、实拍参考图、重建缓存、报告和备份，不提交。`local/raw/chapter_XX` 是各章运行包对应的完整原始包，`local/runtime_extras/` 是从运行包拆出的非必要数据，`local/archive/` 是已被取代的临时实验快照；目录职责见 `local/README.md`。后续标注以 `runtime/` 内文件为准。
- [runtime.py](../dev_tools/campaign/maps/runtime.py) 按定位模型导出运行文件，并在导出时精简到正式推图实际读取的数据：所有章节保留 `map.png`、`map.json`、`annotations.json`、`connectivity.json`；平面章节的 `source/map_data.npz` 只留道路概率、投影与变换校验数组（去掉覆盖计数与敌我位置）。被去掉的原件搬到 `local/runtime_extras/chapter_XX/`，随 `manifest.json` 记录，不进入版本库；已有运行包可用 `python -m dev_tools.campaign.maps.runtime --slim data/resources/maps` 原地精简，重复执行无改动。平面实验包再通过 `prepare_package.py` 导入，共用仓库已有的 `module/campaign/vision/assets/calibration.json` 并生成 `validation.json`；移动测试入口也会创建独立运行副本。
- 运行地图的道路导出、标注备份、平面标定采样及旧局部标定写入 `local/packages/<地图相对路径>/`。完整采集包的实拍参考图可通过显式 `--map` 打开；重建与扫描回放使用 `local/` 内完整数据，不使用精简后的运行包。
- 导出入口只写到新目录，拒绝覆盖已有运行地图；地图与标注保留原始文件字节，避免换行转换破坏哈希绑定。保存后的标注修改仍需 Git 提交。本地 `formal_manifest.json` 是历史采集快照，不能代替运行包的 `validation.json`。

## 现场验证路径

1. 确认客户端语言、客户区 `1776×999`、当前章节／难度与所选地图一致。
2. 在「移动」页选择同一道路近点，再选择离屏远点；检查实际移动、镜头平移、道路停稳、
   独立重定位和到达结果，不能只以点击返回或地图显示通过验收。
3. 分别检查箭头可见、建筑遮挡和小队离屏；无可靠锚点时不猜脚点，缺少画面标记的拖动
   不提供角色避让保证。
4. 收集品模式核对实际提示后停止，敌人模式核对准备弹窗；到达附近不是触发证据。
5. 用停止按钮或 STOP 文件取消，再测试失焦等待、窗口移动和驱动异常；
   核对输入释放及 `result.json`，安全异常后不得追加清理操作。

## 生产任务验收路径

1. 从主页、剧情、战斗及野外分别启动主线，确认可靠身份后才建章；开局和恢复完成前必须有
   可信扫描，普通战后不无条件完整扫描。
2. 核对普通敌人优先、主线身份两帧确认、历史线索只侦察，以及普通／Boss／EX 相邻时
   不互相覆盖编号。类型或位置不可靠时不得直点。
3. 选择有明确机关和光幕标注的道路，验证唯一机关直点／道路到达、触发确认、
   仅对应封锁解除和后续居中扫描；缺标注或关联歧义不得批量放行。
4. 验证有向电梯的入口推进、两帧出口区域确认和出口扫描，另测未传送、误落和失败方向禁用；
   不以出口坐标附近的普通步行代替传送。
5. 在待复核前置道路上验证同拍八屏额度和改选后的续查；未确认焦点及累计失败保留，
   不能靠开合地图或重新扫描清零。
6. 分别测试快速战斗、普通战斗、加载瞬态、胜败结算和战败重试耗尽。两种自动开关独立确认，
   胜利只清对应敌人，未绑定的启动战斗不改历史记录。战后重新定位，不沿用战前坐标。
7. Boss 胜利后经 MISSION CLEAR、章节列表和必要上层页面，确认下一章及原难度才重建会话；
   读不到身份或页面不明确时不能接受旧野外瞬态。
8. 验证原地点击、来回移动、EX 退出／绕行、定位冲突、用户停止和窗口变化；
   只检查真实移动后的路线进展，业务恢复不清空失败，安全异常不补发输入。

以上按实际客户端语言分别验收。截图回放只验证识别、规划与接线，不代替游戏内移动、
设施触发、战斗或换章；UI 语言切换也不代表另一游戏语言已验证。
