# 地图标注工具

入口：[dev_tools/map_annotator.py](../dev_tools/map_annotator.py)。这是独立的本地浏览器工具，不启动游戏控制，不需要管理员权限。依赖 Python 3.9+ 和项目已有的 Pillow、NumPy、OpenCV，不需要额外安装前端依赖或构建 SPA。

从 Wiki 批量下载普通／困难收集物并配准到共享底图，参见 [Wiki 批量导入与地图补采](wiki-collectibles-batch.md)。导入后仍可用本工具人工复核和编辑。

## 启动

在仓库目录、已安装项目依赖的 Python 环境中运行：

```powershell
python dev_tools/map_annotator.py
```

默认递归查找 `data/chapter_maps/runtime/` 下的运行地图，与 Wiki 导入共用目录，自动打开浏览器。完整采集与辅助数据存放在 `data/chapter_maps/local/`，不进入默认地图列表。网页只监听本机 `127.0.0.1:8766`。终端按 Ctrl+C 关闭服务。

指定单张地图或其他集合目录：

```powershell
python dev_tools/map_annotator.py --map data/chapter_maps/runtime/chapter_38
python dev_tools/map_annotator.py --root data/chapter_maps/runtime
```

`--map` 指向包含 `map.png` 和 `map.json` 的目录；未指定 `--root` 时，同级地图包也会进入下拉列表。`--root` 和 `--map` 一起使用时，后者必须在前者目录内。`--port 0` 可自动选择可用端口，`--no-open` 可关闭自动打开浏览器。

## 标注流程

1. 在上方选择地图包。需要核对道路时，将左侧图层切换为“实拍参考图”；两张图共用同一套标注坐标。
2. 在左侧选择五种标注类型之一：**普通收集品、困难收集品、地面机关、地面电梯、电梯传送关系**。前四种默认单击创建点，也可切换折线、多边形或矩形；名称、颜色可自行修改，名称不决定已分类标注的类型。
3. 通过画布上方的“普通／困难／全部”切换收集品显示，画布和对象列表同步筛选，机关、电梯及它们的传送关系共用。默认只显示普通收集品；切换普通或困难时，当前收集品绘制类型也随之切换。选择另一难度的收集品类型会切换到对应视图；“全部”视图可同时查看两种。切换不会修改已保存数据，保存始终包含被隐藏的标注。未完成绘制时先完成或按 Esc 取消，再切换。
4. 在图上绘制，随后用“选择”工具选中对象。拖动对象移动位置，拖动白色顶点修改形状；右侧可精确输入坐标、编辑类型、名称与备注、插入或删除顶点。点、折线、多边形分别至少保留 1、2、3 个不同顶点。
5. 先标注两部“地面电梯”，再选择“电梯传送关系”，依次点击起点电梯和目标电梯。勾选“新传送为单向”后，箭头由第一次点击的电梯指向第二部电梯；未勾选则为双向。已有关系也可在属性里修改方向。收集品、机关不能作为传送端点；已有传送关系的电梯需先删除关系才能改成其他类型。
6. 点击保存或按 Ctrl+S，将标注写入当前地图目录的 `annotations.json`。刷新或重新打开地图会加载已保存内容。右侧“文件与副本”可下载当前 JSON，或重新读取磁盘文件。这些标注不会自动触发导航或战斗逻辑。

| 工具 | 操作 | 快捷键 |
| --- | --- | --- |
| 选择 | 单击选中；拖动对象 / 白色顶点 | V |
| 平移 | 按住鼠标拖动；任何工具下也可按住空格拖动或使用鼠标中键 | H |
| 点 | 单击创建 | P |
| 折线 | 连续单击添加顶点，双击或 Enter 完成 | L |
| 多边形 | 至少三个顶点，双击或 Enter 闭合 | G |
| 矩形 | 从一个角拖到对角 | R |
| 电梯传送 | 依次点击起点电梯、目标电梯，自动选择电梯传送关系类型 | C |

滚轮以鼠标位置为中心缩放；“1:1”恢复原图比例，“适应窗口”显示全图。绘制时 Backspace 撤回最后一个顶点、Esc 取消本次绘制。Ctrl+Z 撤销、Ctrl+Shift+Z 或 Ctrl+Y 重做；文本输入框内保留原生文本撤销。Delete 删除选中标注，删除对象时同步删除相关连接，可撤销恢复。

## 手动修订道路

左侧「道路修订」提供画笔补路（B）、橡皮擦（E）和多边形填充（F）。
画笔直径为 1～160 个原图像素，缩放不会改变实际宽度；单击可画一个点，按住拖动可连续绘制。
多边形连续单击添加顶点，双击或 Enter 完成；「多边形操作」可选择补齐道路或擦除区域。
Esc 取消未完成操作，Ctrl+Z 撤销、Ctrl+Shift+Z / Ctrl+Y 重做。

道路修订与收集品标注分别显示，「显示道路修订」可切换查看原图。
切到实拍参考图时，修订以半透明叠加，便于对照。
Ctrl+S 同时保存标注和道路修订；再次打开自动恢复，原始 `map.png` 不变。

「保存并导出修订图」先保存，再写入新的 `manual_exports/<版本>/`：

- `map.png`：按照修订顺序覆盖后的地图，保留原图尺寸和坐标，不绘制收集品标注。
- `terrain_override.png`：人工修改掩码，0=未修订、1=擦除、2=补路。
- `edits.json`：源图／导出图哈希、保存版本、操作记录、坐标及掩码含义。

导出后点击「查看导出的地图」打开图片。每次导出为独立快照，不覆盖旧版本。
这是一份人工修订图及覆盖掩码，未重估高度／投影，也不会自动开启小队移动或迁移旧图标注。
正式消费人工修订时，应结合覆盖掩码处理，不能把补路当作原始帧已验证的观测概率。

## 道路连通初判与人工修订

各章节地图目录中的 `connectivity.json` 保存道路连通初判和修订后的结果。现有第 1～48 章均已生成。
平面地图使用道路概率缓存与人工道路修订，分层地图使用投影道路栅格；按 8px 网格、距道路边缘超过 6px、
禁止斜穿墙角的规则划分区域。分层地图的二维区域不证明同层可通行，也不会放开现有移动标定限制。

左侧「道路连通区域」提供以下操作：

1. 勾选「显示区域编号与连通修订」，切换「自动初判区域／修订后的区域」比较结果。相同编号表示步行连通。
2. 「绘制分隔线」：沿误连位置单击添加顶点，Enter 或双击完成；线应横跨需要切断的道路，宽度为 8～160px。
3. 查看即时区域预览，使用列表「删除」、Ctrl+Z 撤销或 Ctrl+Shift+Z 重做。Ctrl+S 保存后重新打开仍可继续修改。

人工修订按原图坐标保存在 `annotations.json.connectivity_edits`，区域编号是重新计算的显示编号，不能当作永久 ID。
不同区域之间只能通过已标注的电梯传送关系前往，不支持人为添加跨区域步行连接。
分隔只影响寻路图，不改写道路图像或定位证据；补路、擦路仍使用原有道路修订工具。
平面导航读取保存的有效区域，跨区域时规划电梯中转；分区、A* 和电梯判断使用同一份连通结果。

连通文件记录算法版本、底图哈希、道路掩码哈希和连通修订哈希，包含自动／有效区域的编号、节点数、范围、
标签位置与逐行压缩网格。打开或保存地图时会重建缺失、过期的数据，保留人工修订；运行副本绑定该文件哈希，
运行时不接受过期数据。新扫描导出与实验包导入会携带连通文件。需要重新批量生成时执行：

```powershell
.venv/Scripts/python.exe -m dev_tools.map_connectivity --root data/chapter_maps/runtime
```

## 正式扫描

右侧「地图扫描」可指定章节、扫描步长和「需要 3D 处理」。第 40 章默认勾选 3D，其他章节默认关闭，
仍可手动调整；默认步长为 120。先把游戏打开到对应普通章节的野外页面，再点击「开始扫描」。
扫描会核对章节号并展开小地图，采集时保持游戏窗口在前台。

- 关闭 3D：沿用原有平面重建和导出。
- 开启 3D：采集后执行分层重建，再用原始道路区域投影重绘，导出 `map.png`、`reference.png`、
  `map.json`、原始帧、深度及重绘证据。扫描任务自动串联上述处理。
- 页面显示阶段、已保存帧数与日志位置。「停止扫描」请求协作退出，正在计算的阶段可能需要等待；
  已采集帧保留。「打开扫描结果」只在任务成功且地图包校验通过后可用，切换时仍检查未保存编辑。
- 使用默认运行目录时，完整扫描写入 `data/chapter_maps/local/captures/scans/<任务 ID>/chapter_XX/`；成功后自动将运行必需文件导出到 `runtime/scans/<任务 ID>/chapter_XX/`，供「打开扫描结果」使用，不覆盖既有地图或修订。显式打开其他本地地图集合时，仍在该集合的 `scans/` 下输出。
  `.processing/` 保存中间证据，不会进入运行目录。
- 同一编辑器中的扫描与小队移动互斥。3D 导出仍标记 `navigation_ready=false`，
  该标记表示整章几何与跨层导航未验收；局部定位和移动测试见下节。

## 分层地图的 Wiki 和移动测试

`local_parallax` 地图可进入正式 Wiki 匹配入口。定位先配准到扫描原始帧，再使用重绘时的局部平面投影到
地图；至少两个相机位置的结果一致才可接受。纹理不足时用整图道路搜索提供候选，再以原始帧道路及轮廓
验证。人工擦除的位置不能作为收集点；不同来源几何发生漂移时，还要比较当前修订道路以排除不符的候选。
未通过项继续保存在 Wiki `matches.json` 中待复核，不使用固定画面中心替代无法识别的小队圆环。

手动修订直接从 `annotations.json.terrain_edits` 读取，不需要覆盖 `map.png`。
Wiki 缓存绑定底图、几何和道路修订，收集品对象变化不会触发全部重新匹配；道路修订变化会使旧匹配失效。
导入收集点保留既有道路笔画和人工标注。扫描的隐藏 `.processing` 包不参与 Wiki 地图选择。

右侧管理区分为「对象、Wiki、移动、扫描」四页，左侧道路修订与显示选项可折叠。
在「Wiki」页点击「匹配 Wiki 标注」，会使用当前地图包和已保存道路修订，预览普通／困难的通过数及待复核项；
「导入通过的标注」只增量添加已通过项目，保留已有坐标。匹配期间标注版本变化会阻止导入，需要重新匹配。

「移动」页显示当前地图的标定状态。所有平面地图统一使用第 38 章现用标定，不限制章节；
每张地图仍按自己的小地图投影换算位移，不直接复制第 38 章的地图坐标。
非平面移动只支持已有有效局部标定的 `local_parallax` 地图。管理界面要求标定预先可用；
缺失、版本失效或证据损坏时禁止开始移动，保留原标定文件。

保存道路修订后，让游戏进入对应普通／困难章节，在道路上选点并点击「移动到目标」。
分层地图目标必须位于已有标定的同层支持范围内。收集品／敌人行为仍需实际触发反馈，
不将到达附近当成拾取或战斗成功。标定采集器保留为独立实验入口，不在普通移动中调用。

到点、收集品、敌人三种模式共用远距离移动流程：目标已在有效场景内时直接点击完整目标，
目标离屏时先平移主场景，再用小地图重新定位目标并点击，交给游戏自动寻路。
每次计划最多平移 8 次，触及镜头边界或定位失败则停止；
单次镜头拖动按方向选择可用场景区域：横向最多 1728、纵向最多 810 客户区像素（1776×999 客户区）。
斜向保持拖动方向并取可用区域容纳的最大幅度，整段拖动避开小地图、顶部和底部固定按钮。
每次重新定位后测量实际镜头推进比例，用最近三次有效测量的中位数调整后续拖动幅度。
移动后根据小队标记与道路确认停稳，再重新定位和修正。界面显示本次任务累计的镜头平移次数。
等待期间保持紧凑小地图，间隔展开取得新快照后立即收回；不使用展开面板持续显示的旧画面判断停稳。
移动开始和移动后的真实小队定位也先最小化再打开，使小地图回正并显示小队位置。
小地图切换通过控件外框和面板状态确认；漏点时仅在原控件仍可见的情况下重试，最多点击三次。
分层地图仍受已有同层标定范围约束，超出实测位移支持域时使用受支持的落点，不向实测支持域外推算。

移动的地面锚点通过小队头顶的白色／橙色向下箭头确定：最多采样 48 帧、间隔至少 0.2 秒，
在 16 帧滑动窗口内验证动画，每半窗口至少保留 6 帧有效箭头；少量漏检会继续采样，
用动画上下极值的中点消除浮动，再向下补偿 90 客户区像素，与原地面点击标定保持同一坐标含义。
该偏移在 1776×999 客户区、第 33 章现场测得；不适用于任意窗口缩放。白色、橙色和高亮笔画分别匹配，
同一箭头模板覆盖多个尺寸，保留 0.72 分数门槛与竞争候选检查。独立命令与管理界面共用箭头周期采样。横向漂移、小地图道路变化、身份变化或取消请求会立即停止；
采样耗尽后仅允许下述小地图辅助恢复，否则保存截图并停止。箭头换色、遮挡和不同道路高度的移动精度需按现场验证步骤分别核对。

场景墙面和地面不共面，因此标定测量局部点击位移，不用整幅场景的单个透视变换。
标定仅适用于该地图、难度、道路版本及采样附近的同层区域，不能外推到另一层或整个章节。
跨空洞、擦除区、缺少同层道路证据或超出标定范围时停止。修改道路后需重新标定。
短距离移动中，全局定位发生歧义时可以跟踪已验证的现场原帧，在不同局部范围做留出角点检查，合格结果间
坐标差不超过 3px；仅一个范围合格时须至少有 12 个对应点、4 个留出验证点。
固定参考跟踪失败时，允许两组直接通过固定参考定位的现场帧交叉恢复，位置差不超过 6px；恢复帧不成为
下一跳参考，避免逐步累积漂移。参考帧绑定地图、几何、道路修订和难度。
直接验证的辅助参考帧会保存在 `.movement_reference/<difficulty>/`，供下次移动任务恢复定位；
图片损坏、绑定不符或来自交叉恢复的帧不能作为辅助参考。
箭头持续丢失时，从本次任务上一次有效的箭头锚点出发，以小地图小队位移估计当前位置，
再用两组周围静态地面配准交叉核对。只在位移受支持且两组投影一致时恢复点击锚点，
恢复结果不作为下一跳基准。没有箭头基准、只有视野中心或地面配准失败时停止；
小地图小队标记也不可见时有限重试，持续失败不追加点击。Wiki 和小地图上的小队标记识别保留。

分层执行器只支持已标定的局部同层移动，不把视觉接近的道路视作连通。
平面地图的「到点」模式会消费已保存的点状地面电梯和电梯传送关系：步行道路不连通时，
按单向／双向连接规划中转，逐段点击入口，确认传送后继续最终目标。支持串联多部电梯；
折线、多边形电梯没有唯一点击位置，不参与自动移动。收集品、敌人模式及分层地图不自动执行传送。
出口确认要求连续两次小队定位：入口道路已不可达、出口道路可达，且距出口标注不超过 96 地图像素，
允许游戏传送后自动走离平台。每段入口最多三次移动；已停在入口但未触发传送时只做有限等待，失败后停止。
跨区后清除上一段箭头锚点。到达判断始终针对最终目标，停在入口附近不算完成；
章节、难度、标注版本、停止文件、总点击次数和十分钟上限仍贯穿整个任务。
扫描与移动测试互斥；非平面地图不复用平面地图的点击矩阵。

第 48 章普通模式现场复现：保存点状电梯 `(527.9,707.6) ↔ (671.3,375.5)` 的双向关系，
从下方道路在「到点」模式选择 `(920,200)`。2026-10-08 实测单个请求自动通过电梯并连续两次确认到达，
最终定位 `(929.4,188.8)`，距目标 14.6 地图像素，共四次移动点击；反向返回下方道路也已通过。
记录在 `log/campaign_prototype/ch48_elevator_navigation_20261008/`；多段电梯和单向限制另由离线回归覆盖，
未据此宣称其他章节的机关交互已验证。

## 文件与坐标

- 坐标始终为原图像素：左上角 `(0, 0)`，X 向右，Y 向下。缩放、平移和切换参考图不改变保存坐标；小数保留到 0.1px，这只是记录分辨率，不代表地图的实际定位精度。
- 点、折线、多边形保存为 `point` / `polyline` / `polygon`；矩形保存为四顶点 `polygon`，之后也可自由调整形状。`category` 保存标注类型：`normal_collectible`、`hard_collectible`、`ground_mechanism`、`ground_elevator`、`elevator_connection`。收集品同时写入 `difficulty: normal/hard`。`label` 是可编辑名称，`color` 为 `#RRGGBB`，`note` 是备注。传送关系沿用连接的 `id` / `from` / `to` / `directed` 格式，端点必须是不同的地面电梯。
- 兼容没有 `category` 的旧标注：优先使用已有 `difficulty` 或 `source.difficulty` 识别收集品，也可识别“普通收集品／普通收集物”“困难收集品／困难收集物”及“地面机关”“地面电梯”标签（可带空格分隔的后缀）。无法判断的旧标注保持可见，可在右侧手动指定类型。读取和筛选不迁移文件；手动改类型会更新 `category` 和收集品 `difficulty`，保留 Wiki `source` 来源记录。旧的普通连接仍可编辑，转换为电梯传送时会校验端点类型。
- 保存更新 `annotations.json` 和配套的 `connectivity.json`，不修改底图、参考图或投影。道路操作保存在可选的 `terrain_edits` 数组，
  与标注对象独立，沿用相同的备份、撤销与并发保护。老文件没有此字段时视为没有道路修改。
  底图尺寸、SHA-256 和标注绑定必须一致，参考图也必须与底图同尺寸。
- `local_parallax` 基线的 `rectified_grid_pixel` 在编辑器中按实际栅格像素处理；坐标方向须保持左上角原点、
  X 向右、Y 向下，不修改源地图元数据或进行隐式缩放。
- 每次覆盖前，运行地图的原标注备份到 `local/packages/<地图相对路径>/.annotation_backups/`，再通过临时文件原子替换。显式打开其他本地地图包时，备份仍在包内。恢复备份时先保留当前副本，再将选中的备份复制为 `annotations.json` 并重新加载。
- 未保存修改在离开网页或切换地图时会提示。若其他窗口或程序已经修改标注，保存会拒绝覆盖；先下载当前副本，再重新加载并比较。下载副本不等于保存到地图包。
- `data/chapter_maps/runtime/` 只放需要提交的运行地图；`local/` 放完整采集、实拍参考图、重建缓存、报告和备份，不提交。历史 `current/` 整包与其他历史目录保存在 `local/` 下，作为本地快照；后续标注以 `runtime/` 内文件为准。
- [map_runtime.py](../dev_tools/map_runtime.py) 按定位模型导出运行文件：所有章节保留 `map.png`、`map.json`、`annotations.json`，平面章节另保留 `source/map_data.npz`。平面实验包再通过 `prepare_package.py` 导入，共用仓库已有的 `assets/calibration.json` 并生成 `validation.json`；移动测试入口也会创建独立运行副本。
- 第 40 章使用局部视差定位，另保留 `source/scan.json`、该章 134 张参考帧及对应深度文件；不保留平面缓存。局部移动还需 `movement_calibration/<normal|hard>/` 内的 `calibration.json`、`reference.png`、`surface.png`。当前仍缺该章局部移动标定，需在游戏中采集后才能移动。
- 运行地图的道路导出、标注备份、平面标定采样及旧局部标定写入 `local/packages/<地图相对路径>/`。完整采集包的实拍参考图可通过显式 `--map` 打开；重建与扫描回放使用 `local/` 内完整数据，不使用精简后的运行包。
- 导出入口只写到新目录，拒绝覆盖已有运行地图；地图与标注保留原始文件字节，避免换行转换破坏哈希绑定。保存后的标注修改仍需 Git 提交。本地 `formal_manifest.json` 是历史采集快照，不能代替运行包的 `validation.json`。

## 现场验证路径

1. 使用中文客户端，确认客户区为 `1776×999`，在游戏进入与所选地图、难度一致的野外页面。
2. 在「移动」页选择同一道路的近点，保持游戏前台；检查箭头周期证据、实际移动和连续到达复核。
3. 选择平面地图上的离屏远点，检查镜头平移计数、完整目标点击、停稳后重定位及到点修正。
4. 对白色、橙色箭头和建筑遮挡场景分别重复近点验证；查看 `anchor_method` 和失败截图，确认无证据时停止。
5. 分层地图使用与地图、难度、道路修订匹配的局部标定，在同层支持域内验证；域外或跨空洞目标应被拒绝。
6. 收集品模式在带放大镜的橙色倒三角出现时停止，不点击拾取；自动拾取造成的计数增加也可作为反馈。
   敌人模式核对战斗准备弹窗；到达附近不能代替实际提示证据。
7. 使用停止按钮或 STOP 文件检查释放；另测失焦后的停止行为，并核对任务目录的 `result.json`。

中文客户端的章节、难度 OCR 和弹窗模板需要上述现场检查。
其他语言需单独进行现场验证。
